## 본질: "일하는 방식의 패러다임 전환"

Eigent는 단순한 AI 도구가 아닙니다. 이것은 **"AI 노동력"**이라는 새로운 존재론적 개념을 구현한 첫 번째 시도입니다. 우리가 "일한다"는 것의 의미를 재정의하는 도구이죠.

전통적으로 우리는 "나 혼자" 일하거나, "다른 사람과 협업"했습니다. Eigent는 여기에 세 번째 차원을 추가합니다: **"나의 AI 팀과 함께 일하기"**. 마치 자신만의 전문가 팀을 고용한 것처럼요.

## 핵심 개념: Multi-Agent Workforce

### 1. **철학적 기반: 분업과 협업의 AI적 구현**

Eigent는 Adam Smith의 핀 공장 이론을 AI 시대로 가져왔습니다:

- **Developer Agent**: 코드를 작성하고 실행하는 전문가
- **Search Agent**: 웹을 검색하고 정보를 추출하는 리서처
- **Document Agent**: 문서를 생성하고 관리하는 작가
- **Multi-Modal Agent**: 이미지와 오디오를 처리하는 크리에이터

각 에이전트는 자신의 전문 영역에서 탁월하며, **동시에 병렬로 작업**합니다. 이것이 단순 챗봇과의 결정적 차이입니다.

### 2. **실존적 특징: Human-in-the-Loop**

흥미로운 점은 Eigent가 불확실성을 만났을 때 **스스로 멈추고 인간에게 질문한다**는 것입니다. 이는 AI의 자율성과 인간의 판단력을 조화시키는 설계 철학을 보여줍니다.

완전 자동화가 아니라 **증강된 협업(Augmented Collaboration)**을 지향하는 거죠.

## 실용적 활용: 당신이 할 수 있는 일들

### 📊 **비즈니스 인텔리전스 자동화**

```
예시: "내 은행 거래 CSV 파일로 Q2 재무제표를 만들어줘.
      투자자들에게 보여줄 차트가 포함된 HTML 보고서로."
```

**작동 원리**:

- Document Agent가 CSV를 분석
- Developer Agent가 차트 생성 스크립트 작성
- 여러 에이전트가 병렬로 시각화 작업
- 최종 HTML 보고서 생성

**당신의 HR 업무에 적용하면**:

- 리더십 평가 데이터 → 자동 보고서 생성
- 교육 프로그램 효과성 분석 → 시각화
- 조직 진단 결과 → 인터랙티브 대시보드

### 🔍 **시장 조사 및 리서치 자동화**

```
예시: "영국 헬스케어 산업을 분석해서 우리 회사 계획을 지원할
      종합 보고서를 만들어줘. 상위 5-10개 기회를 식별하고

```

**멀티 에이전트 협업**:

2. Document Agent: 정보 구조화
3. Developer Agent: 데이터 시각화
4. 통합 에이전트: Slack 연동

**HR 자동화 SaaS 개발에 적용**:

- 경쟁사 HR 솔루션 분석
- 시장 트렌드 자동 모니터링
- 잠재 고객 페르소나 리서치
- 가격 전략 분석

### 📄 **문서 처리 및 관리**

## 기술적 아키텍처: 왜 이게 가능한가?

### **MCP (Model Context Protocol) 통합**

Eigent의 진정한 힘은 **도구 생태계**에 있습니다:

- 브라우저 자동화
- 코드 실행
- Notion 연동
- Google Suite (Drive, Docs, Sheets)
- Slack 메시징
- 터미널 명령 실행

**그리고 가장 중요한 것**: 당신만의 커스텀 MCP 도구를 추가할 수 있습니다. 즉, **내부 API나 회사 특화 기능을 AI 에이전트에 장착**할 수 있다는 뜻입니다.

### **CAMEL-AI 프레임워크 기반**

CAMEL (Communicative Agents for "Mind" Exploration of Large Scale Language Model Society)은 멀티 에이전트 시스템 연구의 최전선입니다. Eigent는 이 학술적 기반 위에 실용적 구현을 올린 것입니다.

## 🎭 본질적 이해: "컨텍스트"란 무엇인가?

### 철학적 전제

컨텍스트(Context)는 **"의미의 토양"**입니다. 같은 단어도 맥락에 따라 다른 의미를 갖죠.

- "사과" → 과일? 사죄?
- "리더십" → CEO의 리더십? 팀장의 리더십? 오케스트라 지휘자의 리더십?

AI에게 컨텍스트는 **"지금 이 순간 무엇을 알고 있는가"**의 전부입니다. 인간은 장기 기억이 있지만, AI는 대화창에 보이는 텍스트만이 전부입니다.

**컨텍스트 엔지니어링**은 이 제한된 "지금 여기"를 최대한 효율적이고 풍부하게 만드는 기술입니다.

### 왜 중요한가?

Eigent 같은 멀티 에이전트 시스템에서는:

- Developer Agent가 "지금 어떤 코드를 작성 중인지"
- Search Agent가 "이미 검색한 내용이 무엇인지"
- Document Agent가 "문서의 어디까지 작성했는지"

이 모든 것이 **컨텍스트**입니다. 이걸 잘못 관리하면:

- 같은 작업 반복 (비효율)
- 정보 손실 (품질 저하)
- 비용 폭증 (토큰 낭비)

## 1️⃣ 프롬프트 캐싱 (Prompt Caching)

### 🧠 핵심 개념: "자주 쓰는 건 외워두기"

**비유**: 매일 출근길

- **캐싱 없음**: 매일 아침 집에서 회사까지 GPS로 경로 검색
- **캐싱 있음**: 첫날만 검색하고, 이후엔 기억에서 바로 출발

AI도 마찬가지입니다. 매번 똑같은 시스템 프롬프트를 다시 읽는 건 낭비죠.

### 기술적 작동 원리

```
┌─────────────────────────────────────┐
│ 시스템 프롬프트 (항상 동일)         │ ← 캐싱 대상
│ "당신은 HR 전문가입니다..."         │
│ "리더십 평가 규칙은..."             │
│ (2000 토큰)                         │
├─────────────────────────────────────┤
│ 사용자 질문 (매번 변경)             │ ← 새로 처리
│ "김철수의 평가 결과는?"             │
│ (50 토큰)                           │
└─────────────────────────────────────┘

캐싱 전: 2050 토큰 × 100회 = 205,000 토큰
캐싱 후: 2000 토큰(1회 저장) + 50 토큰 × 100회 = 7,000 토큰
절감율: 96.6%
```

### 실무 적용 예시

**CSP님의 "25년 리더십, 생각하다" 프로그램**

캐싱 대상:

```
시스템 프롬프트 (변하지 않음):
- 평가 프레임워크 설명 (1000 토큰)
- 역량 정의 및 평가 기준 (800 토큰)
- 피드백 작성 가이드라인 (500 토큰)
- 회사 가치 및 리더십 철학 (300 토큰)
총: 2600 토큰 → 1회만 전송

동적 부분 (매번 변경):
- 개인 평가 데이터 (100 토큰)
- 구체적 질문 (50 토큰)
```

**효과**:

- 100명 평가 시 토큰 비용 97% 절감
- 응답 속도 50% 향상
- 동일한 평가 기준 일관성 보장

## 2️⃣ 시스템 프롬프트 최적화 (System Prompt Optimization)

### 🎯 핵심 개념: "핵심만 간결하게"

**비유**: 업무 지시서

- **최적화 전**: "이 작업은 매우 중요하며, 신중하게, 꼼꼼하게, 정확하게, 빠뜨리지 말고, 확실하게..." (불필요한 수식어 과다)
- **최적화 후**: "평가 기준: 1) 정확성 2) 완전성" (명확하고 간결)

### 최적화 전략

#### A. **중복 제거**

**Before**:

```
당신은 HR 전문가입니다.
당신은 리더십 평가를 수행합니다.
당신은 17년의 경험을 가진 전문가입니다.
당신은 LG에서 근무했습니다.
당신은...
(500 토큰)
```

**After**:

```
역할: LG PRI 출신 17년차 HR 리더십 평가 전문가
(20 토큰, 96% 감축)
```

#### B. **구조화**

**Before**:

```
평가할 때는 전략적 사고와 실행력과 소통능력과
변화관리와 코칭을 봐야 하고 각각 20점씩이며
총점은 100점이고...
(장황한 단락)
```

**After**:

```
평가 영역 (각 20점):
1. 전략적 사고
2. 실행력
3. 소통능력
4. 변화관리
5. 코칭

(구조화된 리스트)
```

#### C. **예시 기반 학습 (Few-shot)**

**Before**:

```
피드백을 작성할 때는 긍정적이면서도
건설적이어야 하며, 구체적인 사례를 들고,
개선 방향을 제시하며...
(추상적 설명 300 토큰)
```

**After**:

```
예시:
입력: 전략적사고 18점, 실행력 12점
출력: "전략 수립 역량이 우수합니다(상위 10%).
실행 단계에서 추진력 강화가 필요합니다.
권장: 프로젝트 관리 교육 이수"

(구체적 예시 1개로 100 토큰)
```

```
예시:
[이름]님, DX 모듈2가 멈춰있네요.
목표일(3/15)까지 [남은일수]일입니다.
도움이 필요하시면 연락 주세요.

(총 150 토큰, 81% 절감)
```

## 3️⃣ 툴킷 문서 문자열 최적화 (Toolkit Docstring Optimization)

### 🔧 핵심 개념: "도구 사용법을 명확하게"

**비유**: IKEA 조립 설명서

- **나쁜 설명서**: "부품 A를 사용하여 적절한 방법으로 결합하시오"
- **좋은 설명서**: "부품 A(긴 나사) → 구멍 B → 시계방향 3바퀴"

AI 에이전트에게 도구(tool)는 외부 기능입니다. Eigent의 경우:

- 브라우저 제어
- 파일 생성
- API 호출
- 데이터베이스 쿼리

각 도구의 **사용법 설명(docstring)**이 명확해야 에이전트가 올바르게 사용합니다.

### 문제점: 불명확한 Docstring

**Before**:

```python
def send_email(recipient, subject, body, attachments=None):
    """
    이메일을 발송하는 함수입니다.
    여러 수신자에게 보낼 수 있으며,
    첨부 파일도 가능합니다.
    """
    ...
```

**AI의 혼란**:

- "여러 수신자"는 리스트? 쉼표 구분 문자열?
- 첨부 파일 형식은? 경로? 바이너리?
- 필수 파라미터는 뭐지?

**결과**: 에이전트가 잘못 사용 → 에러 → 재시도 → 비효율

### 최적화된 Docstring

**After**:

```python
def send_email(
    recipient: str | list[str],
    subject: str,
    body: str,
    attachments: list[str] | None = None
):
    """
    Gmail API를 통해 이메일 발송

    Args:
        recipient: 수신자 이메일 (단일 또는 리스트)
            - 단일: "user@example.com"
            - 복수: ["user1@example.com", "user2@example.com"]
        subject: 제목 (최대 200자)
        body: 본문 (HTML 또는 Plain text)
        attachments: 첨부 파일 경로 리스트 (선택)
            - 예: ["/path/to/file.pdf", "/path/to/image.png"]
            - 최대 25MB, 파일당 10MB 제한

    Returns:
        dict: {"message_id": "...", "status": "sent"}

    Raises:
        ValueError: recipient가 빈 문자열인 경우
        FileSizeError: 첨부 파일이 10MB 초과인 경우

    Example:
        >>> send_email(
        ...     recipient="team@company.com",
        ...     subject="Weekly Report",
        ...     body="<h1>Report</h1><p>...</p>",
        ...     attachments=["/reports/week1.pdf"]
        ... )
        {"message_id": "abc123", "status": "sent"}
    """
    ...
```

### 최적화 효과

| 항목        | Before     | After | 개선                    |
| ----------- | ---------- | ----- | ----------------------- |
| 에러율      | 30%        | 5%    | -83%                    |
| 재시도 횟수 | 평균 2.3회 | 0.2회 | -91%                    |
| 토큰 낭비   | 높음       | 낮음  | 에러 재시도 감소로 절감 |

### CSP님 실무 예시: Notion API 도구 최적화

**Before**:

```python
def create_notion_page(title, content, database_id):
    """Notion 페이지를 생성합니다."""
```

**AI의 실패 케이스**:

```
에이전트: create_notion_page(
    title="평가보고서",
    content="김철수님의 평가 결과...",  # 마크다운? HTML?
    database_id="5f2ff32ac1b8..."  # 대시 포함? 제외?
)
→ ERROR: content must be Notion blocks format
```

**After**:

```python
def create_notion_page(
    title: str,
    content: str,
    database_id: str,
    properties: dict | None = None
):
    """
    Notion 데이터베이스에 새 페이지 생성

    Args:
        title: 페이지 제목 (최대 2000자)
        content: 페이지 본문 (Notion Markdown 형식)
            - 지원: # 제목, **굵게**, - 리스트
            - 미지원: HTML 태그
        database_id: DB ID (대시 포함/제외 모두 허용)
            - 형식: "5f2ff32a-c1b8-4981-988b-f5e0da6eeb15"
            - 또는: "5f2ff32ac1b84981988bf5e0da6eeb15"
        properties: DB 속성값 (선택)
            - 예: {"주제": "개발", "중요도": "⭐⭐⭐"}

    Returns:
        dict: {"page_id": "...", "url": "https://notion.so/..."}

    Example:
        >>> create_notion_page(
        ...     title="평가보고서_김철수",
        ...     content="# 평가 결과\n**강점**: ...",
        ...     database_id="5f2ff32ac1b84981988bf5e0da6eeb15",
        ...     properties={"상태": "✅ 완료"}
        ... )
    """
```

**결과**: 에이전트가 첫 시도에 성공, 재작업 불필요

## 4️⃣ 컨텍스트 압축 (Context Compression)

### 📦 핵심 개념: "핵심만 남기고 버리기"

**비유**: 여행 짐 싸기

- **압축 전**: 옷 30벌, 책 10권, 신발 5켤레 → 캐리어 3개 (무거움)
- **압축 후**: 필수 옷 7벌, 전자책, 운동화 1켤레 → 배낭 1개 (가벼움)

AI의 컨텍스트 윈도우는 **제한적**입니다:

- Claude Sonnet: ~200K 토큰
- GPT-4: ~128K 토큰

긴 대화를 하다 보면 이 한계에 도달합니다. 그때 무엇을 남기고 버릴까?

### 압축 전략

#### A. **요약 (Summarization)**

**Before** (10,000 토큰):

```
사용자: 리더십 평가 기준이 뭐였죠?
AI: 전략적 사고, 실행력, 소통능력, 변화관리, 코칭입니다.
사용자: 각각 몇 점이죠?
AI: 각 20점씩, 총 100점입니다.
사용자: 김철수 점수는?
AI: 18, 15, 17, 14, 16점입니다.
사용자: 평균은?
AI: 80점입니다.
...
(50턴의 대화)
```

**After** (500 토큰):

```
대화 요약:
- 평가 영역: 5개 (각 20점)
- 김철수: 총점 80/100
  - 강점: 전략적사고(18), 소통(17)
  - 개선: 변화관리(14)
- 다음 액션: 피드백 레터 작성 예정
```

#### B. **선택적 보존 (Selective Retention)**

중요도에 따라 차등 보존:

| 중요도 | 내용 유형              | 보존 방식 |
| ------ | ---------------------- | --------- |
| 높음   | 최종 결정, 핵심 데이터 | 전문 보존 |
| 중간   | 중간 결과, 논의 과정   | 요약 보존 |
| 낮음   | 시행착오, 에러 메시지  | 삭제      |

**예시**:

```
[높음 - 전문 보존]
최종 결정: 김철수 평가 80점, 승진 추천

[중간 - 요약]
논의: 변화관리 점수 14점 → 코칭 필요성 합의

[낮음 - 삭제]
(에러: CSV 파일 경로 오류 → 재시도 → 성공)
```

#### C. **청킹 (Chunking)**

긴 문서를 의미 단위로 분할:

**Before** (한 번에 전체 처리):

```
리더십평가보고서.pdf (15,000 토큰)
→ 컨텍스트 윈도우 부족 → 에러
```

**After** (청크로 분할):

```
Chunk 1: 요약 및 종합 점수 (500 토큰)
Chunk 2: 영역별 상세 평가 (3,000 토큰)
Chunk 3: 개선 계획 (1,000 토큰)

필요시 관련 청크만 로드
→ 효율적 메모리 사용
```

### 압축 알고리즘 예시

#### **LLMLingua 방식**

불필요한 단어 제거:

**Before**:

```
김철수 님께서는 전략적 사고 영역에서
매우 우수한 성과를 보여주셨습니다.
특히 장기 비전 수립과 관련하여...
(100 토큰)
```

**After**:

```
김철수: 전략적사고 우수.
장기비전 수립 강점.
(20 토큰, 80% 압축)
```

#### **의미 기반 압축**

임베딩을 사용한 유사 문장 통합:

```
문장1: "전략적 사고 능력이 뛰어납니다"
문장2: "전략 수립 역량이 우수합니다"
문장3: "장기 비전 설정에 탁월합니다"

→ 유사도 90% 이상
→ 통합: "전략적 사고/비전 수립 역량 우수"
```

### CSP님 실전 활용

**시나리오**: 100명 리더십 평가 데이터 분석

**문제**:

- 100명 × 평균 500 토큰/명 = 50,000 토큰
- Claude 윈도우 초과 가능성

**해결책 1: 계층적 요약**

```
Level 1: 개인별 요약 (100명 × 50 토큰 = 5,000 토큰)
Level 2: 부서별 평균 (10부서 × 100 토큰 = 1,000 토큰)
Level 3: 전사 종합 (500 토큰)

최종 컨텍스트: 6,500 토큰 (87% 압축)
```

**해결책 2: 쿼리 기반 압축**

```
질문: "변화관리 점수가 낮은 리더 10명은?"

→ 변화관리 관련 데이터만 로드
→ 상위/하위 10명만 상세 보존
→ 나머지는 점수만 보존

결과: 2,000 토큰으로 충분
```

