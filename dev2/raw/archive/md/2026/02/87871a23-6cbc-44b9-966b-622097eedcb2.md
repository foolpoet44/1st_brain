## 📖 페이지 핵심 내용 요약

이 글은 **장시간 실행되는 AI 에이전트가 여러 컨텍스트 윈도우에 걸쳐 작업할 때 직면하는 문제와 해결책**을 다룹니다. 핵심은 소프트웨어 엔지니어링 실천법에서 영감을 얻은 구조입니다.

### 🎯 핵심 문제점

장시간 에이전트는 "교대근 엔지니어"처럼 동작합니다. 각 세션이 시작될 때 이전 작업에 대한 메모리가 없어서 다음 문제들이 발생합니다:

1. **한 번에 너무 많이 하려다가** 중단(one-shotting) → 다음 세션이 구현 중인 기능으로 시작
2. **너무 일찍 완료 선언** → 전체 요구사항을 놓침
3. **테스트 없이 완료 마킹** → 버그 발생

### ✅ 두 부분 솔루션

**1️⃣ 초기화 에이전트 (Initializer Agent)**

- `init.sh` 스크립트: 개발 서버 실행
- `claude-progress.txt`: 진행 상황 로그
- `feature_list.json`: 200개 이상의 기능을 구조화된 테스트로 정의
- 초기 git 커밋

**2️⃣ 코딩 에이전트 (Coding Agent)**

- 세션 시작: 진행 상황 파일 읽기 → git 로그 확인 → 기본 테스트
- 한 번에 **한 기능만** 구현
- 구현 후: git 커밋 + 진행 상황 업데이트

### 🔑 환경 관리의 핵심 요소

**기능 목록 (JSON 형식)** - 모든 기능을 "passes: false"로 시작

```json
{
  "category": "functional",
  "description": "New chat button creates a fresh conversation",
  "steps": [단계별 테스트],
  "passes": false
}
```

**점진적 진행** - 한 번에 한 기능씩, 각 세션마다 깔끔한 상태로
**자동화된 테스트** - Puppeteer MCP로 브라우저 자동화하여 실제 사용자처럼 테스트

## 💡 당신에게 적용할 사항 제안

당신의 HR 자동화 SaaS 구축 여정과 현재 프로젝트에 매우 직접적으로 적용할 수 있습니다:

### 1️⃣ **HR 자동화 SaaS의 "초기화 프롬프트" 설계**

지금 당신이 리더십 평가, ESCO 기반 스킬 프레임워크, 자동 보고서 생성을 구축 중인데, 이를 **모듈화된 기능 목록**으로 재구성할 수 있습니다:

```json
{
  "category": "leadership_evaluation",
  "description": "Generate 360-degree feedback report with AI analysis",
  "steps": [
    "Extract employee data from source",
    "Run competency assessment",
    "Generate narrative analysis",
    "Validate against baseline",
    "Export as PowerPoint"
  ],
  "passes": false
}
```

이렇게 하면 Claude Code나 에이전트가 다음번 세션에서 "뭐가 안됐나?"를 찾으려 헤매지 않습니다.

### 2️⃣ **Notion 세컨브레인을 "claude-progress.txt" 방식으로 운영**

이미 자동 아카이빙 규칙을 수립했는데, 여기에 추가로:

- **진행 상황 레디마크**: 각 프로젝트마다 "다음 세션이 해야 할 일" 명확히 기록
- **Feature completion log**: 어떤 기능이 "passes: true"가 됐는지 체계적으로 추적
- **컨텍스트 다리 역할**: 당신이 다른 프로젝트로 갔다가 돌아올 때 5분 안에 상태 파악

### 3️⃣ **"한 번에 한 기능" 원칙을 HR 자동화에 적용**

당신의 철학 "do it once, automate it forever"와 정확히 일치합니다:

- **리더십 평가 시스템**: 360 피드백 수집 → 분석 → 리포트 생성을 **분리된 마이크로태스크**로
- **ESCO 기반 프레임워크**: 스킬 매핑 → 레벨 설정 → 직무 연결 → 교육 추천을 **별도의 에이전트 루프**로
- **PowerPoint 자동화**: 템플릿 → 데이터 바인딩 → 검증을 **다단계 파이프라인**으로

### 4️⃣ **테스트 우선 마인드셋 강화**

당신의 자동화 시스템이 "완료했다"고 선언하기 전에:

- HR 담당자 관점의 **end-to-end 테스트**: 데이터 입력 → 처리 → 결과 확인
- **자동 검증**: 생성된 리포트의 논리적 일관성 체크
- **샘플 데이터 with 예상값**: "이 입력이면 이 출력이 나와야 한다" 명시

### 5️⃣ **SaaS 제품화 때 핵심 인프라**

지금부터 습관화하면 5-6년 후 사업 시작할 때 엄청난 자산이 됩니다:

```
HR_Automation_SaaS/
├── init.sh                    # 클라이언트 환경 초기화
├── product-features.json      # 모든 기능 체크리스트
├── implementation-progress.md # 각 기능의 구현 상태
├── docs/
│   ├── api-specification.md   # API 스펙 문서화
│   └── deployment-guide.md
└── tests/
    ├── unit/
    ├── integration/
    └── e2e/
```

### 6️⃣ **당신의 "철학을 코드로" 여정에의 함의**

이 글의 본질은 **지식을 구조화하는 것**입니다:

- 심리학 → **competency framework JSON**
- 철학 → **systematic feature decomposition**
- HR 경험 → **validation rules & edge cases**

에이전트가 다음 세션에서 "왜 이렇게 설계했나?"를 물을 때, 명확한 **아키텍처 문서**가 있으면 그 답을 이미 세워둔 거죠.

## 🎯 즉시 실행 항목

1. **진행 중인 AX 인증 프레임워크**를 feature_list.json으로 재구성
2. **현재 Notion 진행 상황 기록 체계**에 "다음 세션 TO-DO" 섹션 추가
3. **자동화 시스템의 검증 규칙**을 명시적으로 문서화 (현재는 암묵적)

이렇게 하면 당신이 다른 프로젝트를 하다가 돌아왔을 때, 또는 나중에 팀원을 고용했을 때 **체계적으로 인수인계**할 수 있습니다.

# feature_decomposer.py
# Notion에서 진행 중인 프로젝트를 Feature List로 변환

import json
from datetime import datetime

def create_feature_template(category, description, steps, priority="medium"):
    """HR 자동화용 Feature 템플릿"""
    return {
        "id": f"feat_{datetime.now().strftime('%Y%m%d%H%M%S')}",
        "category": category,
        "domain": "HR_Automation",  # 당신의 도메인
        "description": description,
        "priority": priority,  # critical, high, medium, low
        "steps": steps,
        "validation_criteria": [],
        "passes": False,
        "estimated_tokens": 0,
        "completed_date": None,
        "notes": ""
    }

# 리더십 평가 시스템 분해
leadership_evaluation_features = [
    create_feature_template(
        category="data_ingestion",
        description="360-degree feedback responses 수집 및 검증",
        steps=[
            "Google Forms/Excel에서 응답자 데이터 수집",
            "데이터 정규화 (유효성 검사)",
            "중복 응답 제거",
            "데이터 암호화 후 저장"
        ],
        priority="critical"
    ),

    create_feature_template(
        category="analysis",
        description="Competency 점수 계산 (5점 척도)",
        steps=[
            "각 competency별 응답 통계 계산",
            "자기평가 vs 타인평가 차이 분석",
            "신뢰도 점수 산출 (응답자 수 기반)",
            "이상치 제거 및 재계산"
        ],
        priority="critical"
    ),

    create_feature_template(
        category="analysis",
        description="AI 기반 Narrative 생성",
        steps=[
            "Competency 프로필을 Claude에 전달",
            "개인 맞춤형 narrative 프롬프트 생성",
            "강점/개선영역 분석 텍스트 작성",
            "심리학적 인사이트 추가"
        ],
        priority="high"
    ),

    create_feature_template(
        category="reporting",
        description="PowerPoint 리포트 자동 생성",
        steps=[
            "python-pptx로 템플릿 로드",
            "차트 데이터 바인딩 (matplotlib → PPTX)",
            "Narrative 텍스트 삽입",
            "스타일 일관성 검증",
            "PDF 내보내기"
        ],
        priority="high"
    ),

    create_feature_template(
        category="validation",
        description="전체 파이프라인 E2E 테스트",
        steps=[
            "샘플 데이터 3가지 케이스 준비",
            "수동으로 각 단계 검증",
            "예상 출력값과 비교",
            "오류 시나리오 테스트"
        ],
        priority="critical"
    )
]

# Notion에 저장할 JSON 파일 생성
feature_list = {
    "project": "Leadership_Evaluation_System_25years",
    "version": "1.0",
    "created": datetime.now().isoformat(),
    "total_features": len(leadership_evaluation_features),
    "completed": 0,
    "features": leadership_evaluation_features
}

with open("feature_list.json", "w", encoding="utf-8") as f:
    json.dump(feature_list, f, indent=2, ensure_ascii=False)

print(f"✅ {len(leadership_evaluation_features)}개 Feature 생성 완료")

### 2.2 Init Agent 프롬프트 (Claude에게 줄 지시)

당신은 HR 자동화 SaaS 프로젝트의 **초기화 담당자**입니다.

### 생성 원칙

- ❌ 절대 제거하지 말 것: "이건 테스트 제거는 불가능합니다"
- ✅ 세부적: "데이터 입력" 아니라 "Google Forms에서 JSON으로 변환"
- ✅ 테스트 가능: 각 feature는 명확한 입력/출력/검증 기준
- ✅ 원자적: 한 세션에 1-2시간으로 완료 가능한 크기

## Success Criteria

당신의 초기화가 성공했다는 것은:

- [ ] feature_list.json에 50개 이상의 기능 정의됨
- [ ] 모든 기능이 구체적이고 테스트 가능한 형태
- [ ] init.sh가 실행되어 기본 환경 구성
- [ ] Git 리포지토리 생성 및 첫 커밋 완료
- [ ] 다음 agent가 "뭘 해야 하나?"를 5분 안에 파악 가능

## ⚠️ Critical Rules

1. **Completeness First**: 완벽함보다 완성도. 모든 기능이 정의되어야 다음 agent가 일할 수 있음
2. **Immutable Features**: Feature list 수정은 오직 coding agent만 (pass/fail 상태만 변경)
3. **Progressive Disclosure**: 한 번에 너무 많은 context 주지 말 것
4. **Documentation Over Code**: 초기 단계에는 문서와 구조가 코드보다 중요

## 💡 당신의 역할 정의

이 구조에서 **당신은**:

```
세션 관리자 (Session Manager)
├─ Init Agent: "전체 계획 짜기"를 지시
├─ Coding Agent: 매 세션 "구체적 작업"을 지시
└─ 품질 관리: 각 세션 완료 후 결과 검증
```

**구체적으로**:

1. **Init Agent 호출** (1회)
   - "25년 리더십 경험을 기능 목록으로 변환해줘"
   - 결과: feature_list.json

2. **Coding Agent 호출** (매 1-2주마다)
   - "Feature #5를 구현해줘"
   - 검증: "결과 테스트했어? 모든 케이스 커버했어?"
   - 기록: Notion의 Session Progress에 결과 저장

3. **진행 상황 추적**
   - Weekly 리뷰: "이번주 몇 개 완료? 다음주 계획은?"
   - 막힌 부분 정리: "왜 이 기능이 오래 걸렸나?"
   - SaaS 시작까지의 진도: "5-6년 동안 얼마나 진행했나?"
