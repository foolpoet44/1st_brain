## 2. 디자인 시스템 — 공유 토큰과 컴포넌트

모든 파일이 하나의 디자인 언어를 공유합니다. CSS 변수로 선언된 토큰들이 핵심입니다.

**컬러 팔레트** (`:root` 공통 정의):

```css
--red: #a50034 /* LG 브랜드 컬러 — 주요 강조 */ --red-light: #f9e6ec
  /* 카드 보더, 배경 */ --yellow: #fbbf24 /* 배지, 하이라이트 */ --dark: #1a1a2e
  /* Hero 배경 베이스 */;
```

**타이포그래피**: `Noto Sans KR` (300/400/500/700/900) — Google Fonts CDN. `clamp(32px, 5vw, 48px)` 같은 뷰포트 반응형 폰트 크기를 `hero-title`에 적극 사용합니다.

**외부 라이브러리** (CDN):

- Font Awesome 6.5.1 — 아이콘 전담
- GSAP 3.12.5 + ScrollTrigger — `HR_VIBE_Direction.html`에서만 사용 (애니메이션)
- 나머지 파일은 **순수 CSS/JS** — 바닐라 구현

## 3. 페이지별 레이아웃 패턴

파일들을 분석하면 4가지 뚜렷한 레이아웃 패턴이 반복됩니다.

**패턴 A — 허브 랜딩** (`index.html`): `top-bar → hero → menu-grid (4-col) → stats-row → footer`. 메뉴 카드에 hover 시 상단 6px 바가 `var(--red)`로 전환되는 인터랙션. Card 4는 `<a>` 대신 `onclick` toggle로 드롭다운 서브메뉴.

**패턴 B — 콘텐츠 상세** (`HR_VIBE_Direction.html`, `HR_VIBE_GroundRule.html`): `top-bar (← 뒤로) → hero (gradient) → main-content (max-width: 1200px, centered)`. 콘텐츠 영역이 섹션 카드의 연속으로 구성. Direction 파일은 GSAP ScrollTrigger로 스크롤 진입 애니메이션.

**패턴 C — 탭/Phase 네비게이션** (`Rollout_Plan.html`): `top-bar → hero → timeline-nav (sticky tab bar) → phase-content (active/hidden)`. JS `showPhase(n)` 함수가 `classList.toggle('active')`로 패널 전환. Outlook 캘린더 `.ics` 다운로드 기능 내장 (`addToOutlook()` — `BEGIN:VCALENDAR` 포맷).

**패턴 D — 매트릭스 테이블** (`Digital_Transformation_Roadmap.html`): `top-bar → hero → transformation-matrix (3×3 table) → execution-phases`. 행: Company/Division/Individual 레벨, 열: 3단계. 각 셀에 `highlight-yellow` 클래스로 핵심 액션 강조.

## 4. 공통 컴포넌트 해부

모든 페이지가 공유하는 컴포넌트 DNA:

```
[top-bar]
  └── .tb-left: LG 로고 + 수직 구분선 + 페이지 타이틀
  └── .tb-right: 배지 (index) / 뒤로가기 링크 (하위 페이지)

[hero]
  └── 배경: linear-gradient(165deg, #0d0d0d → #1a1a2e → #0f3460)
  └── ::before: radial-gradient 레이어 (반투명 red glow)
  └── .hero-eyebrow: 대문자 + letter-spacing (컨텍스트 라벨)
  └── .hero-title: clamp() 반응형
  └── .hero-desc: 설명문
```

**Do / Don't / Why 3단 구조** (`HR_VIBE_GroundRule.html`): 각 Ground Rule 카드 내부가 `action-section.do` + `action-section.dont` + `action-section.why`로 구성. 녹색/빨간색 박스 + 노란색 맥락 박스 — 심리적 안전망을 시각 언어로 구현한 흥미로운 선택.

## 6. 개선 관찰 — CSP 시선에서

구조를 학습하면서 몇 가지가 눈에 들어옵니다.

첫째, **CSS 중복**이 상당합니다. `top-bar`, `hero`, `tb-back` 스타일이 각 파일에 복사붙여넣기 되어 있고 `style.css`는 별도로 존재하지만 실제 HTML 파일들은 이를 `link`하지 않습니다. 공유 컴포넌트를 `style.css`로 통합하면 유지보수성이 크게 올라갑니다.

둘째, **버전 파일들의 정리 기준**이 불명확합니다. `HR_VIBE_GroundRule_OLD`, `backup`, `v4` — 어느 것이 최종인지 파일명으로는 판단하기 어렵습니다. `README.md`에도 이 파일들에 대한 설명이 없습니다.

셋째, **guide.html의 이미지 의존성**이 높습니다. 슬라이드 이미지 (`img_master_guide/` 등)가 없으면 핵심 콘텐츠가 빠집니다. zip 파일에 이미지가 포함되지 않아 단독 브라우저 실행 시 빈 섹션이 나타날 수 있습니다.

넷째, GSAP이 `HR_VIBE_Direction.html` 한 파일에만 쓰입니다. 나머지는 CSS `transition`만으로 해결 — 이는 좋은 판단입니다. 라이브러리 의존성을 최소화했습니다.

---

전체적으로 볼 때, 이 코드베이스는 **단일 개발자가 단기간에 반복적으로 빌드한 흔적**이 명확합니다 — 패턴의 일관성, 버전 파일들의 존재, CSS 중복. EX Intelligence 시스템이나 이후 SaaS 제품으로 확장할 때는 공유 컴포넌트 추출과 명확한 파일 네이밍 컨벤션이 첫 번째 리팩터링 대상이 될 것입니다. 코드 품질 자체는 깔끔합니다 — 시맨틱 HTML, CSS 변수 활용, 바닐라 JS 우선 접근이 모두 좋은 선택입니다.
