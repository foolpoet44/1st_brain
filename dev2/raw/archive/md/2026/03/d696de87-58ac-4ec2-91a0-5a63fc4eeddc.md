## MarkItDown이란 무엇인가

GitHub에서 87k 스타를 받은, Microsoft AutoGen 팀이 만든 Python 오픈소스 라이브러리입니다. SW 백그라운드 없이도 이해할 수 있도록 비유하자면, 이 도구는 일종의 **범용 문서 번역기**입니다. PDF든 Word든 Excel이든 PowerPoint든, 심지어 이미지나 오디오 파일까지 — 모든 걸 LLM이 이해하기 좋은 텍스트 형식(Markdown)으로 변환해줍니다.

### 왜 Markdown인가?

GPT-4o와 같은 주류 LLM들은 Markdown을 네이티브하게 "말하며", 별도 지시 없이도 Markdown을 자연스럽게 사용합니다. 이는 LLM들이 방대한 양의 Markdown 포맷 텍스트로 훈련되었음을 의미하며, 추가 이점으로 Markdown 문법은 토큰 효율성도 매우 높습니다.

즉, 문서를 AI에게 넣기 전에 Markdown으로 먼저 변환하면 — AI가 훨씬 잘 이해하고, 비용도 덜 든다는 뜻입니다.

---

## 지원 파일 형식

현재 MarkItDown이 변환을 지원하는 형식은 PDF, PowerPoint, Word, Excel, 이미지(EXIF 메타데이터 및 OCR), 오디오(EXIF 메타데이터 및 음성 전사), HTML, 텍스트 기반 포맷(CSV, JSON, XML), ZIP 파일, YouTube URL, EPub 등 다양합니다.

CSP 업무 맥락에서 특히 주목할 만한 것은 **PowerPoint → Markdown** 변환입니다. EX Intelligence 발표 자료나 교육 자료들을 AI 파이프라인에 넣을 때, 먼저 MarkItDown으로 전처리하면 구조가 훨씬 깔끔하게 보존됩니다.

## 사용법

### 설치

전체 기능을 설치하려면 `pip install 'markitdown[all]'`을 사용하면 됩니다. 선택적으로 특정 형식만 설치하고 싶다면 `pip install 'markitdown[pdf, docx, pptx]'`처럼 원하는 것만 지정할 수도 있습니다.

### 커맨드라인 (가장 간단한 방법)

파일 변환은 `markitdown path-to-file.pdf > document.md`처럼 한 줄로 실행하거나, `-o` 옵션으로 출력 파일을 지정할 수 있습니다. 또한 파이프를 활용한 `cat path-to-file.pdf | markitdown` 방식도 지원합니다.

### Python API

```python
from markitdown import MarkItDown

md = MarkItDown(enable_plugins=False)
result = md.convert("report.pptx")
print(result.text_content)
```

### LLM 연동 (이미지 설명 자동 생성)

이미지 설명을 위해 LLM을 활용하려면 `llm_client`와 `llm_model`을 함께 제공하면 됩니다. 현재 이 기능은 pptx와 이미지 파일에서 지원됩니다.

```python
from markitdown import MarkItDown
from openai import OpenAI

client = OpenAI()
md = MarkItDown(llm_client=client, llm_model="gpt-4o")
result = md.convert("slide_with_images.pptx")
```

### MCP 서버 지원

MarkItDown은 현재 Claude Desktop 같은 LLM 애플리케이션과의 통합을 위한 MCP(Model Context Protocol) 서버도 제공합니다. Claude Desktop에 연결하면 채팅 중에 "이 PDF 변환해줘"라고 말하는 것만으로 동작하게 할 수 있습니다.

## CSP 업무에서의 활용 포인트

MarkItDown이 CSP의 워크플로우에 연결되는 지점이 여럿 있습니다.

**ESCON / EX Intelligence 파이프라인**으로의 편입을 생각해보면, 조직 내 각종 문서(HR 정책서, 역량 모델 PPT, 설문 결과 Excel)를 AI 에이전트에 넣기 전 전처리 레이어로 MarkItDown을 두는 것이 자연스럽습니다. `convert()` 한 번으로 구조가 살아있는 Markdown이 나오고, 그것을 Supabase나 벡터 DB에 적재하면 RAG 기반 조회가 훨씬 정밀해집니다.

**Pulse Check 보고서 자동화** 관점에서는, 임원이 제출한 기존 PPT 자료나 Word 보고서를 Markdown으로 변환해 비교 분석하는 용도로도 쓸 수 있습니다. "intuition에서 data로"라는 EX Intelligence 서사를 구현하는 하나의 하위 레이어가 되는 셈입니다.

**Vibe Coding 교육 자료 재활용** 측면에서도, 기존에 만들어둔 pptx 강의 자료를 `markitdown`으로 변환하면 Claude Code 워크스페이스에서 바로 참조 가능한 지식 소스가 됩니다.

한마디로, MarkItDown은 독립적인 도구라기보다 **AI 파이프라인의 입구 게이트**입니다. 문서가 세상에서 AI로 들어오는 모든 경로에 설치할 수 있는 얇지만 강력한 변환 레이어라고 보면 됩니다.

## Antigravity에서 MarkItDown 사용하는 두 가지 경로

핵심부터 말하면, MarkItDown을 Antigravity에서 쓰는 방법은 크게 두 가지입니다. **터미널 직접 설치형(CLI)**과 **MCP 서버 연동형**. 전자는 간단하고 즉각적이며, 후자는 에이전트가 자율적으로 파일 변환을 수행하게 되는 구조입니다.

---

### 경로 1: 터미널 직접 설치 (가장 빠른 방법)

Antigravity는 VS Code의 heavily modified fork이기 때문에 내장 터미널이 그대로 살아있습니다. 에이전트에게 시키거나, 직접 터미널을 열어서 실행하면 됩니다.

**설치 순서:**

```bash
# 1. 가상환경 생성 (프로젝트 폴더 안에서)
python -m venv .venv
source .venv/bin/activate   # Mac/Linux
# .venv\Scripts\activate    # Windows

# 2. MarkItDown 설치 (전체 기능 포함)
pip install 'markitdown[all]'

# 3. 즉시 사용
markitdown 파일명.pdf > 결과.md
markitdown 파일명.pptx -o 결과.md
```

Antigravity 에이전트에게 자연어로 시켜도 됩니다:

> "이 프로젝트에 markitdown을 설치하고 `/path/to/file.pptx`를 변환해줘"

에이전트가 venv 생성 → pip 설치 → 변환까지 자동으로 처리합니다.

---

### 경로 2: MCP 서버로 연동 (에이전트 자율 사용 구조)

이 방법이 Antigravity의 본령에 맞는 방식입니다. MCP 서버로 등록해두면, 에이전트가 대화 중에 "이 파일 변환해서 분석해줘"라는 말 한마디에 자율적으로 MarkItDown을 호출합니다.

MarkItDown은 공식적으로 MCP 서버(`markitdown-mcp`)를 제공하며, Claude Desktop 같은 LLM 애플리케이션과의 통합을 위해 설계되었습니다.

**Step 1: markitdown-mcp 설치**

```bash
pip install 'markitdown-mcp'
# 또는 uv 사용 시
uv pip install 'markitdown-mcp'
```

**Step 2: mcp_config.json 수정**

Antigravity에서 MCP 서버를 추가하려면, Agent 창 상단 오른쪽 `...` 메뉴 → MCP Servers → Manage MCP Servers → View raw config를 클릭하면 `mcp_config.json` 파일이 열립니다.

파일 경로는 OS별로 다릅니다:

- **Mac/Linux**: `~/.gemini/antigravity/mcp_config.json`
- **Windows**: `C:\Users\<USER_NAME>\.gemini\antigravity\mcp_config.json`

아래 내용을 추가합니다:

```json
{
  "mcpServers": {
    "markitdown": {
      "command": "/절대경로/.venv/bin/python",
      "args": ["-m", "markitdown_mcp"]
    }
  }
}
```

> ⚠️ 중요: Antigravity는 `${workspaceFolder}` 같은 상대경로를 지원하지 않으므로 반드시 절대경로를 사용해야 합니다.

**Step 3: Antigravity 재시작 후 확인**

변경사항 적용을 위해 Antigravity를 닫고 다시 열고, MCP Servers 패널에서 `markitdown`이 표시되는지 확인합니다.

---

### 어떤 경로를 선택할까?

CSP 업무 맥락에서 판단하면 이렇습니다.

**CLI 방식(경로 1)**은 당장 오늘 써야 하는 상황, 즉 EX Intelligence 발표 자료를 Markdown으로 변환해서 Claude에 붙여넣을 때 적합합니다. 설치 3분, 사용 1분.

**MCP 방식(경로 2)**은 ESCON이나 Pulse Check 파이프라인처럼 "문서 입수 → 변환 → 분석 → 저장"의 플로우를 에이전트가 자율적으로 반복 수행해야 할 때 적합합니다. 한 번 연결해두면 "이 폴더의 모든 PPT를 Markdown으로 변환해서 Supabase에 넣어줘"가 한 문장으로 작동하는 세계가 됩니다.

Antigravity의 본질이 "에이전트가 자율적으로 계획하고, 실행하고, 검증하는 플랫폼"이라는 점을 고려하면, 장기적으로는 MCP 방식이 CSP 아키텍처의 철학 — "do it once, automate it forever" — 과 훨씬 잘 맞습니다.
