# Work Network 데이터 정비 — 관리원칙

> 원본 파일: `Work_Network_데이터정비_ACT0019_20261012_추론보충.xlsx` (Drive `26년/261011`). 이 사본은 첫 시트 `00_관리원칙`만 옮긴 것이다.

**요약 원칙:** 원본 보존 · 업무 정의 · 관계 정의 · 실행 증거를 분리하고, 원문/추출/확정 및 제출/정의/관계/실행/품질 상태를 구분.

## 관리 구획

| 구획 | 원칙 |
| :-- | :-- |
| 원본 보존 | 원본 2개 시트는 변경하지 않고 뒤쪽에 유지. 보정 전 활동명은 원본에서 이미 미보존 상태이므로 복원불가를 명시. |
| 업무 정의 | 기존 Activity_Code를 보존하고 코드+추출명 조합에 관리용 Activity_Object_ID를 별도 부여. |
| 관계 정의 | 모든 연결은 관계 유형·조건·근거·확인 상태를 가진 Relation_ID로 관리. |
| 실행 증거 | 정의상 존재하는 출력과 실제 Run에서 확인된 증거를 분리. 미확보는 미확인 유지. |
| 값 구분 | 원문값·추출값·확정값을 별도 열로 관리. AI 추론명과 확인 완료명을 혼합하지 않음. |
| 상태 분리 | 제출 상태·정의 상태·관계 상태·실행 상태·품질검증 상태를 개별 열로 관리. |
| ACT-0019 범위 | 첨부의 ACT-0019 2개 행을 우선 대응. 승인 필수 기준, LMS/환급 승인 필요 여부와 선후관계는 미확인. |
| 실행 1건 | PLC LV1 2차 결과보고: 결재/첨부는 확인, 입력 원천·LMS 반영·HRD-NET 환급은 미확인. |

## 추론 보충 관리

원본·추출값·확정값은 수정하지 않고 `08_추론보충`에서 추론 보충값과 신뢰성(높음/중간/낮음)을 별도 관리한다. 검토 전에는 확정값으로 승격하지 않는다.

## 검토 순서

1. `01_ID코드_대응표`에서 코드 중복·충돌과 원본/보정/버전을 확인
2. `02_보정명_확인대장`에서 AI 추론명/코드 매핑명을 검토 후 확인완료명·확인자·확인일 입력
3. `03_Workflow_IPO`에서 대표 단계와 미확인 조건을 검토
4. `04_관계원장`에서 조건·근거·확인 상태로 연결을 승인/보완
5. `05_실행추적_1건`과 `06_실행증거`에서 실제 Run 증거 공백을 해소
6. `07_품질검증`에서 수량·누락·미확인 상태를 재점검
