# PRI FDE 부트캠프 설계 & 도메인 성장경로 솔루션 컨셉

대화 아카이브 · 2026 · 중요도 ★★★ 핵심 · 상태 진행중 태그: FDE, 부트캠프, ESCON, 스킬온톨로지, ESCO/RSF, 페르소나, 성장경로, 현상학적 귀납

## 1\. 출발점 — 부트캠프의 위치와 본질

PRI FDE 부트캠프는 5단계 FDE 양성 여정(**선발 → 학습 → 동행 → 자립 → 인증**) 중 두 번째 칸인 **"학습(Integration Bootcamp)"** 단계를 정밀하게 깎아내는 작업이다. 본질은 지식 전달이 아니라 **정체성 변환**. 선발 통과자는 4칼리지(Physical AI · Agentic AI · Digital Twin · 허브 Data Intelligence)에서 각자 다른 봉우리를 오른 사람들 — T자형 세로획(전문 깊이)은 있고 가로획(횡단 역량)이 없는 상태. 부트캠프는 그 가로획을 긋고 "나는 OO 엔지니어다"를 "나는 현장에 들어가 문제 전체를 책임지는 FDE다"로 변환시키는 **용광로**다.

**설계 결정(합의):** 상세 일정을 미리 박지 않는다. 모듈을 시간 비종속 '내용 단위'로 먼저 빚고, 일정은 현장 가동·현업 부하·사업장 출입 시점 위에 올려놓는 마지막 단계로 미룬다.

## 2\. 부트캠프 운영 4원칙 (헌법)

1.  **빌딩 우선** — 강의는 빌딩 과제용 최소 연료. 만들면서 배운다.
2.  **현장 시뮬레이션** — 익명화된 실제 데이터·모호한 요구로 동행·자립을 미리 겪게.
3.  **페어 형성(Echo–Delta)** — 성향 진단을 실제 짝지어 실험. 깨지고 다시 맞춰지는 안전 구간.
4.  **수렴과 압축** — 흩어진 언어를 공통 어휘·스택으로. 압박 없으면 수렴 없다.

## 3\. 4축 9모듈 (시간 비종속 내용 맵)

축 순서 = FDE 일의 순서: 현장진입 ▸ 데이터연결 ▸ 지능탑재 ▸ 솔루션전달

  - **축1 정체성·현장감각** — M1 제조 현장 몰입 / M2 문제 정의·스코핑
  - **축2 데이터·통합기반(OT/IT)** — M3 제조 데이터 파운데이션 / M4 OT·IT 통합
  - **축3 지능·자동화 빌딩** — M5 온톨로지·시맨틱 모델링 / M6 AI 에이전트·Vibe Coding / M7 디지털트윈·시각화 PoC
  - **축4 솔루션 통합·전달** — M8 통합 솔루션 빌딩(미니 1人1案) / M9 현장 커뮤니케이션·데모

## 4\. 도메인별 성장 경로 — 원리: "도메인을 살리면서"

  - 실패 모델: 엔지니어를 개발자로 만든다 → 어설픈 개발자 + 무뎌진 본래 무기.
  - 전제: **도메인이 곧 해자(moat). 부트캠프는 정체성 교체가 아니라 확장.**
  - 공통 규칙: **도메인 정박 학습** — 같은 가로축 기술을 학습자 자신의 데이터로 가르친다(SDT 유능감 보호).

|   | 이미 채워진 모듈 | 가장 큰 도약 | 시그니처 1人1案 |
| :-: | :-: | :-: | :-: |
| **장비 엔지니어** | M1, M4(OT측) | M6 소프트웨어 빌딩 · 축4 전달 · M2 문제 소유 | 예지보전 / FDC / 이상탐지 |
| **로봇·제어 엔지니어** | M1, M7 트윈 | M6 결정론→확률론 · 축2 데이터 레이어 | 비전·적응 로봇 셀 / 로봇 트윈 |

함의: 한쪽 강점이 다른 쪽 약점 → Echo–Delta 페어링 근거. 9모듈 공통 + **도메인별 정박 overlay** 필요.

## 5\. 신규 프로젝트 — 도메인 입력 → 성장경로 생성기 (+ESCON 매핑)

**강점:** 다양성 문제에 논리적으로 정확한 응답 / 자산 재활용 높음 / HR 자동화 SaaS의 수직 슬라이스(PoC).

**비평**

1.  **결정론 함정** — "도메인 드롭다운 → 정해진 경로"는 top-down 회귀. 도메인은 약한 신호. 해법: 빠른 길(아키타입 콜드스타트=임시 프록시) + 깊은 길(스킬 자가진단·평가데이터 보정). 진짜 입력은 **스킬 프로파일**.
2.  **다양성은 동기이자 난관** — 자유 입력→스킬 그래프 LLM '의미 매핑 엔진' 필요. 난이도 한 단계 점프 인지.
3.  **ESCON은 의존성 아닌 건설 현장** — 관계 커버리지 제로·조작 URI. 경로 엔진이 필요로 하는 선후관계·인접성·간극이 가장 비어 있음. 뒤집으면 이 도구가 **ESCON 복구의 강제 함수**. 소비자를 먼저 정의해 생산자를 역명세 → 진짜 1순위.
4.  **"예쁜 다이어그램" vs "의사결정 도구"** — 합격 기준은 '몰랐던 걸 알려주고 다르게 행동하게 하는가'. 출력 핵심은 시각화가 아니라 **'가장 큰 도약 지점 + 이유 + 첫걸음' 처방**, 프로파일·목표의 델타에서 계산.

**정렬 질문:** 새 프로젝트 vs ESCON의 view? → **ESCON 소비자 레이어로 설계**가 유리. "FDE Growth Path"는 첫 뷰.

**평결(살리되 두 가지 비틀기)**

  - ① **철학 뒤집기** — top-down 분류기가 아니라 '현상학적 거울'. 서술 입력→이미 가진 봉우리를 먼저 비추고(귀납)→FDE 목표 겹쳐 델타 표시. 결핍 먼저=위축, 가진 것 먼저=끌어올림.
  - ② **ESCON을 목표로** — 도구 요구사항이 ESCON 관계 레이어 복구를 견인하도록 시퀀싱.

은유: 사다리가 아니라 **다리**. 사다리는 "아직 낮다", 다리는 "이미 높고 한 걸음이면 된다".
