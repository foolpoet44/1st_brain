**Antigravity + Lovable을 활용한 AX 역량 개선 전략**

**들어가며 — 두 도구가 말하는 것**

Antigravity는 단순한 에디터가 아니라, "에이전트가 자율적으로 계획하고, 실행하고, 복잡한 태스크를 검증하는" 개발 플랫폼입니다. 그리고 Lovable은 대화만으로 웹 앱을 생성하는 no-code 빌더죠. 이 두 도구는 같은 방향을 가리키고 있습니다. "코드를 쓰는 사람"이 아니라 "의도를 설계하는 사람"이 주인공이 되는 세계. LG PRI HR팀이 2026년에 달성하려는 AX 내재화는 바로 이 전환을 조직 단위로 일으키는 실험입니다.

그런데 여기서 반드시 짚고 넘어가야 할 구분이 있습니다. **CSP 본인의 개인 프로젝트**와 **구성원의 역량 개발**은 전혀 다른 설계 원리를 따릅니다. 하나는 복잡한 시스템을 빠르게 구현하는 것이고, 다른 하나는 저항을 최소화하면서 행동 변화를 일으키는 것입니다.

**Part 1. CSP의 개인 프로젝트 워크플로우**

**Antigravity의 위치**

CSP는 이미 [[CLAUDE.md|CLAUDE]] Code 기반의 hr-workspace 아키텍처를 운영하고 있습니다. 여기서 Antigravity는 Claude Code를 대체하는 것이 아니라 **병렬 프로토타이핑 레이어**로 기능합니다.

2026년 많은 개발자들이 "Antigravity로 빠른 프로토타이핑 + Claude Code로 복잡한 태스크"를 조합해 사용하고 있으며, 비용 측면에서도 강력한 조합으로 평가받고 있습니다. CSP의 상황에 이를 대입하면 이렇게 됩니다.

| **도구**        | **역할**                              | **적용 맥락**                                                    |
| --------------- | ------------------------------------- | ---------------------------------------------------------------- |
| **Claude Code** | 복잡한 추론, MCP 연동, ESCON 아키텍처 | Supabase 스키마 설계, PathologyDetector 로직, Pulse Check 백엔드 |
| **Antigravity** | 빠른 UI 프로토타입, 병렬 에이전트     | EX Intellig[[Understand-Anything/understand-anything-plugin/skills/understand/locales/en.md|en]]ce 보고서 HTML, 평가 도구 프론트엔드                |
| **Lovable**     | 검증용 MVP, 발표자료 데모용 앱        | 경영진 발표용 인터랙티브 데모, 설문 UI 목업                      |

Antigravity의 Planning Mode는 각 단계마다 개입할 기회를 충분히 주기 때문에, 복잡한 프로젝트에서 더 많은 감독과 피드백이 필요할 때 적합합니다. ESCON이나 Pulse Check처럼 HR 도메인 맥락이 깊이 담긴 프로젝트에서는 이 모드가 핵심입니다. AI가 맥락 없이 달려나가는 것을 막아야 하기 때문이죠.

한 가지 중요한 제약도 있습니다. 현재 Antigravity는 MCP를 지원하지 않으며, Claude Code나 Cursor가 지원하는 수백 개의 MCP 서버 생태계에 접근할 수 없다는 것이 가장 큰 약점입니다. Supabase, Notion, GitHub 연동이 중요한 CSP의 핵심 워크플로우에서는 여전히 Claude Code가 주축이 되어야 합니다.

**Part 2. 구성원 AX 역량 개발 전략**

이 파트가 진짜 설계가 필요한 영역입니다. HR 구성원은 개발자가 아닙니다. 이들에게 "IDE를 배워라"고 말하는 순간 저항이 생깁니다. 전략의 핵심은 **도구를 가르치는 것이 아니라, 일하는 방식이 바뀌는 경험을 설계하는 것**입니다.

**왜 Antigravity인가 — 비개발자에게 최적인 이유**

Manager View는 터미널에서 작업하기 싫은 사람들에게 에이전트 오케스트레이션을 접근 가능하게 만들어 준다. GUI를 선호한다면 Antigravity가 가장 접근하기 쉬운 옵션이라는 평가가 있습니다. HR 구성원에게 터미널은 공포의 대상입니다. Antigravity의 시각적 인터페이스는 이 심리적 장벽을 상당히 낮춥니다.

Antigravity는 에이전트가 작업 목록, 구현 계획, 스크린샷, 브라우저 녹화와 같은 검증 가능한 결과물인 'Artifacts'를 생성하기 때문에, 비개발자도 "AI가 지금 무엇을 하고 있는지" 눈으로 확인할 수 있습니다. 이것은 신뢰의 문제이자 학습의 문제입니다.

**역량 개발 3단계 로드맵**

**1단계 — 체험 (1~2개월): "나도 뭔가 만들 수 있다"**

**목표는 기술 습득이 아니라 심리적 임계점 돌파입니다. SW 백그라운드 없이도 결과물을 만들어내는 경험이 전부입니다.**

- **Lovable 중심 과정: "우리 팀 업무를 앱으로 만들어보기" 워크숍. 채용 현황 트래커, 온보딩 체크리스트, 설문 수집 폼 같은 실무와 직결된 미니 앱을 하루 안에 만드는 경험**
- **핵심 원리: 완성도보다 완성 경험. 못 만든 앱이 10개보다, 자신이 만든 앱 1개가 역량 개발에서 훨씬 강력합니다**
- **평가 지표: 수료율이 아니라 "내가 직접 만든 것의 수"**

**2단계 — 내재화 (3~4개월): "업무에 붙여보기"**

**Antigravity를 이 단계에서 도입합니다. Lovable로 만든 프로토타입을 실제 업무 맥락에서 개선하거나, 반복 업무를 에이전트에게 위임하는 경험을 설계합니다.**

- **에이전트 위임 실습: 인사 데이터 정리, 보고서 초안 작성, 설문 결과 요약 같은 반복 업무를 Antigravity 에이전트에게 지시하는 프롬프트 설계 훈련**

**Antigravity는 에이전트가 유용한 맥락과 코드 스니펫을 Knowledge Base에 저장해 미래 태스크를 개선할 수 있도록 학습을 핵심 원리로 설계되어 있습니다.**

**Google Workspace 제약 조건 대응**

LG PRI 사내에서 Google Workspace 사용이 불가하다는 점은 중요한 제약입니다. Antigravity는 Google 계정을 통해 [[GEMINI.md|GEMINI]] 3 Pro의 이용 한도 관리와 디바이스 간 프로젝트 동기화가 이루어집니다. 따라서 구성원 교육 맥락에서 Antigravity 사용 시 **개인 Gmail 계정을 활용**해야 하며, 이에 대한 IT 부서와의 사전 협의 및 보안 가이드라인 설정이 선행되어야 합니다.

실무 데이터를 Antigravity에 직접 입력하는 것은 보안 리스크가 있으므로, 교육 과정에서는 **샘플 데이터 또는 익명화된 데이터만 사용**하는 원칙을 명확히 설정해야 합니다.

**두 파트를 관통하는 하나의 원리**

CSP의 개인 프로젝트와 구성원 역량 개발은 다른 레이어에 있지만, 같은 철학에서 출발합니다. "코드 작성자"에서 "의도 설계자"로의 전환. 개발자에게 이것은 아키텍트가 되는 것이고, HR 구성원에게 이것은 "이 일을 어떻게 자동화할 수 있는가"를 먼저 생각하는 습관을 갖게 되는 것입니다.

Antigravity의 워크플로우에서 개발자는 '코드 작성자'에서 '아키텍트' 혹은 '미션 컨트롤러'로 역할이 전환됩니다. 함수를 직접 타이핑하는 것이 아니라, "OAuth를 지원하도록 로그인 플로우를 리팩터링하고 이 디자인 스펙과 대조해서 검증해라"와 같은 지시를 내리는 것이죠.

**첫 번째** — 전략 전체 구조를 두 트랙(CSP 개인 / 구성원 역량)으로 나눠 보여줍니다. 각 박스는 클릭하면 관련 질문을 이어서 이야기할 수 있습니다.

**두 번째 — 도구 선택 매트릭스입니다. "누가, 어떤 복잡도의 업무에, 어떤 도구를 쓰는가"를 2×3 격자로 정리했습니다. CSP는 세 도구를 모두 쓰지만 용도가 다르고, 구성원은 Lovable(진입) → Antigravity(내재화) 경로만 밟습니다.**

**세 번째 - 구성원의 심리 여정에 초점을 맞췄습니다. 기술 스펙보다 "저항 → 호기심 → 습관 → 설계자"라는 내면의 변화 경로가 역량 개발의 실질적 설계 원리이기 때문입니다.**
