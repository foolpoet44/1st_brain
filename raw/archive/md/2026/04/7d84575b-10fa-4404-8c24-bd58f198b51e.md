## Claude Code에 Gemma 연결하기 — Ollama 경유 방식

### 개념부터 잡기

2026년 1월, Ollama가 Anthropic Messages API 호환성을 공식 지원하면서 일이 완전히 달라졌습니다. 이전까지는 각종 어댑터와 환경변수 해킹이 필요했는데, 이제는 Claude Code가 Ollama의 Anthropic 호환 API를 통해 오픈 모델을 자연스럽게 사용할 수 있습니다. Gemma도 Ollama 라이브러리에 있으므로 동일한 방식으로 연결됩니다.

---

### 방법 1 — 가장 빠른 방법 (권장)

**Step 1: Ollama 설치**

```bash
# macOS / Linux
curl -fsSL https://ollama.com/install.sh | sh

# 설치 확인
ollama --version
```

**Step 2: Gemma 모델 다운로드**

Gemma 4는 Google DeepMind가 만든 오픈 모델 패밀리로, 멀티모달(텍스트+이미지)을 지원하며 Ollama에서 바로 사용 가능합니다.

```bash
# Gemma 4 (최신)
ollama pull gemma4

# 또는 가벼운 버전
ollama pull gemma3:4b   # RAM 8GB 환경
ollama pull gemma3:12b  # RAM 16GB+ 환경
```

**Step 3: Ollama로 Claude Code 실행**

`ollama launch claude` 명령어로 모델 선택 UI가 뜨고, 직접 지정도 가능합니다.

```bash
# 모델 선택 메뉴
ollama launch claude

# 또는 Gemma 직접 지정
ollama launch claude --model gemma4
```

---

### 방법 2 — 수동 환경변수 방식

Claude Code가 Ollama 서버에 연결하도록 환경변수를 설정하는 방법입니다.

```bash
# 환경변수 설정
export ANTHROPIC_AUTH_TOKEN=ollama
export ANTHROPIC_API_KEY=""
export ANTHROPIC_BASE_URL=http://localhost:11434

# Claude Code 실행
claude --model gemma4
```

또는 한 줄로:

```bash
ANTHROPIC_AUTH_TOKEN=ollama ANTHROPIC_BASE_URL=http://localhost:11434 ANTHROPIC_API_KEY="" claude --model gemma4
```

---

### 중요한 현실적 제약

로컬 모델을 사용하면 Claude Code가 일반 LLM처럼 작동하며, 파일 읽기/쓰기, 툴 사용 같은 에이전트 기능이 제한될 수 있다는 보고가 있습니다. 이 부분이 핵심 트레이드오프입니다.

**툴 콜링(Tool Calling) 지원 여부가 관건입니다.** CSP가 Claude Code를 에이전트 방식(파일 수정, 코드 실행 등)으로 주로 쓴다면, Gemma보다는 툴 콜링이 검증된 모델이 더 안정적입니다.

고급 툴 기능을 로컬에서 쓰려면 GLM-4.7-flash를 추천하는 이유가 툴 콜링 지원과 128K 컨텍스트 길이 때문입니다.

**하드웨어 요구사항:**

- 실제로 사용 가능한 수준이 되려면 RAM 32GB(Apple Silicon 통합 메모리 포함)가 권장됩니다. 16GB에서는 작은 모델만 가능하고 경험이 거칠어질 수 있습니다.

---

### Gemma vs 다른 로컬 모델 — 실전 비교

| 모델                | 툴콜링  | 컨텍스트 | 추천 용도                 |
| ------------------- | ------- | -------- | ------------------------- |
| **Gemma 4**         | 제한적  | 128K     | 텍스트 작업, 가벼운 코딩  |
| **GLM-4.7-flash**   | ✅ 강력 | 128K     | Claude Code 에이전트 작업 |
| **Qwen3.5**         | ✅      | 32K      | 코딩 특화                 |
| **kimi-k2.5:cloud** | ✅      | 128K+    | 클라우드 하이브리드       |

---

### CSP 상황에 맞는 권장 전략

Vibe Coding 교육 관점에서, 수강자들에게 "무료로 Claude Code 써보기" 실습을 설계한다면 Gemma보다는 **GLM-4.7-flash**(완전 무료, 툴콜링 지원)가 훨씬 안정적입니다. Gemma는 Google 생태계 실험이나 멀티모달 테스트 시나리오에서 더 의미가 있습니다.

프라이버시 데이터(조직 건강도 Pulse Check 관련 텍스트 등)를 로컬에서 처리하고 싶다면 이 방식은 충분히 실용적입니다. 단, 에이전트 기능보다 "로컬 LLM 추론" 용도로 활용 범위를 잡는 것이 현실적입니다.

Glm-4.7-flash의 사이즈는??

## Claude (Message 4)

```

```

한 마디로 정리하면 이렇습니다.

GLM-4.7-Flash는 **30B-A3B MoE 모델**입니다. 숫자 해석이 핵심인데, 총 파라미터는 30B이지만 토큰 하나를 처리할 때 실제로 활성화되는 파라미터는 약 3B에 불과합니다. MoE 아키텍처 덕분에 30B급 성능을 내면서 추론 비용은 3B 수준으로 유지하는 구조입니다.

**디스크 용량(GGUF 기준):**

Q4_K_M (4비트 양자화): 약 10GB / Q5_K_M (5비트): 약 12GB / Q8_0 (8비트, 고품질): 약 18GB

**실행에 필요한 RAM:**

Ollama 기준으로 최소 16GB RAM이 필요합니다. 풀 프리시전으로 실행하려면 32GB가 필요합니다.

결론적으로 "30B인데 왜 빠르냐"의 답은 MoE 구조에 있습니다. 실제 체감 속도는 훨씬 가벼운 모델처럼 느껴집니다. CSP의 맥북 사양이 16GB 이상이라면 Ollama로 충분히 돌릴 수 있습니다.

## GLM-4.7-Flash보다 가벼운 모델 추천

### 🟢 8GB RAM — 초경량

| 모델                  | 크기   | 툴콜링 | Ollama 명령                    |
| --------------------- | ------ | ------ | ------------------------------ |
| **Qwen3.5 4B**        | ~3.4GB | ✅     | `ollama pull qwen3.5:4b`       |
| **Qwen 2.5 Coder 7B** | ~5GB   | ✅     | `ollama pull qwen2.5-coder:7b` |
| **Gemma3 4B**         | ~3GB   | ❌     | `ollama pull gemma3:4b`        |

Qwen 3.5 4B는 3.4GB로 4GB RAM만 있으면 동작하며, LiveCodeBench 55.8점을 기록합니다. 가볍지만 코딩 보조, 간단한 리팩토링, 에러 설명 용도로는 이 사이즈에서 가장 경쟁력 있는 모델입니다.

---

### 🔵 16GB RAM — 중간 (GLM-4.7-Flash와 동급 대안)

| 모델                   | 크기   | 툴콜링 | 특징            |
| ---------------------- | ------ | ------ | --------------- |
| **Qwen3.5 9B**         | ~6.6GB | ✅     | 코딩 특화, 빠름 |
| **Qwen 2.5 Coder 14B** | ~9GB   | ✅     | 코딩 벤치 최강  |
| **gpt-oss 20B**        | ~12GB  | ✅     | MoE, 3.6B 활성  |

Qwen3.5 9B는 8GB VRAM에서 동작하며, 툴 콜링 포맷 안정성이 다른 모델보다 우수합니다. Qwen 2.5 Coder 14B는 Q4 양자화 기준 약 9GB로, CodeStral-22B나 DeepSeek Coder 33B보다 작지만 벤치마크에서 앞서는 이례적인 모델입니다.

---

### 양자화 선택 기준

Q4_K_M(4비트): 가장 작고 16GB GPU에 적합 / Q5_K_M(5비트): 크기 소폭 증가, 품질 개선 / Q8_0(8비트): 약 18GB, 원본에 가장 가까운 품질

```bash
# 예시: Qwen 2.5 Coder 14B Q4
ollama pull qwen2.5-coder:14b   # 기본이 Q4_K_M
```

---

### CSP 환경 추천 요약

**Claude Code 에이전트용** → `qwen2.5-coder:14b` (툴콜링 안정적, 코딩 최적)  
**Vibe Coding 교육 실습용** → `qwen3.5:4b` (학습자 노트북에서도 동작)  
**빠른 테스트용** → `qwen3.5:9b` (속도·품질 밸런스)

Unsloth 기준 GLM-4.7-Flash GGUF 전체 라인업은 다음과 같습니다 (30B 파라미터 기준).

| 비트       | 모델명     | 크기   | 필요 RAM | 추천 용도        |
| ---------- | ---------- | ------ | -------- | ---------------- |
| **1-bit**  | UD-TQ1_0   | 8.3GB  | 10GB+    | 극한 경량        |
| **1-bit**  | UD-IQ1_S   | 9.25GB | 12GB+    | 극한 경량        |
| **2-bit**  | Q2_K       | 11.3GB | 14GB+    | 실험용           |
| **2-bit**  | UD-Q2_K_XL | 11.9GB | 14GB+    | 실험용           |
| **3-bit**  | Q3_K_M     | 14.6GB | 16GB+    | 최소 실용        |
| **3-bit**  | UD-Q3_K_XL | 13.8GB | 16GB+    | 최소 실용        |
| **4-bit**  | IQ4_XS     | 16.3GB | 20GB+    | ✅ **일반 추천** |
| **4-bit**  | Q4_K_M     | 18.3GB | 22GB+    | ✅ **균형**      |
| **4-bit**  | UD-Q4_K_XL | 17.5GB | 20GB+    | ✅ **균형**      |
| **5-bit**  | Q5_K_M     | 21.4GB | 24GB+    | 고품질           |
| **6-bit**  | Q6_K       | 24.7GB | 28GB+    | 고품질           |
| **8-bit**  | Q8_0       | 31.8GB | 36GB+    | 거의 원본        |
| **16-bit** | BF16       | 59.9GB | 64GB+    | 원본             |

---

### 양자화별 품질/속도 트레이드오프

실사용 기준으로는 FP8은 거의 무손실, Q8은 우수, Q4는 양호, Q3는 극한 제약 상황에서만 사용 가능한 수준입니다.

---

### Ollama로 바로 설치하는 법

```bash
# 4-bit 균형 버전 (가장 많이 쓰임)
ollama pull hf.co/unsloth/GLM-4.7-Flash-GGUF:Q4_K_M

# 더 가벼운 버전 (RAM 16GB 환경)
ollama pull hf.co/unsloth/GLM-4.7-Flash-GGUF:IQ4_XS

# 극경량 (RAM 12GB 이하)
ollama pull hf.co/unsloth/GLM-4.7-Flash-GGUF:UD-TQ1_0
```

---

### 한 줄 요약

대부분의 사용자에게는 Q4_K_M(약 18GB)이 가장 균형 잡힌 선택입니다. RAM이 16GB라면 IQ4_XS(16.3GB)가 현실적인 마지노선입니다.
