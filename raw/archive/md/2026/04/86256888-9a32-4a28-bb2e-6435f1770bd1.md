# Claude Remote Work — 리모트 MCP란 무엇인가

CSP가 늘 관심 가져온 "AI 직원 워크스테이션" 개념과 직결되는 주제입니다. 좀 더 깊이 들어가 보겠습니다.

---

## 본질적인 질문: "Claude가 어디서 작동하는가?"

기존 Claude Code는 **로컬에서** 작동했습니다. CSP의 맥북에 Claude Code가 설치되고, 터미널에서 실행되고, 파일 시스템도 로컬, 도구 실행도 로컬. 즉 CSP가 컴퓨터 앞에 있어야만 Claude가 일할 수 있었죠.

**Claude Remote Work(원격 실행)**는 이 제약을 깨는 패러다임입니다.

---

## 세 가지 레이어로 이해하기

### 1️⃣ Remote MCP Server

MCP(Model Context Protocol)는 Claude가 외부 도구를 사용하는 표준 프로토콜입니다. 기존엔 로컬 프로세스로 실행했지만, **Remote MCP**는 인터넷 어딘가의 서버에서 MCP가 돌아갑니다.

```
[기존]
CSP 맥북 → Claude Code → Local MCP Server → 파일/도구

[Remote MCP]
어디서든 → Claude → Remote MCP Server (클라우드) → 파일/도구/API
```

CSP가 말했던 **Dispatch 패턴**이 바로 이것의 응용입니다. 모바일에서 명령을 보내면, 어딘가의 서버가 Claude를 대신 실행하고, 결과를 돌려주는 구조.

---

### 2️⃣ Claude.ai + MCP Connector (지금 이 화면)

현재 CSP가 claude.ai 웹에서 쓰고 있는 것도 일종의 Remote MCP입니다. Notion, Gmail, Slack, Google Calendar 같은 커넥터들이 모두 **원격 서버**에서 실행되고 있어요.

CSP의 연결된 커넥터 목록을 보면:

- `https://mcp.notion.com/mcp` — Notion 서버
- `https://mcp.slack.com/mcp` — Slack 서버
- `https://gcal.mcp.claude.com/mcp` — Google Calendar

이것들이 전부 Remote MCP 서버입니다. Claude가 직접 Notion API를 호출하는 게 아니라, Notion이 운영하는 MCP 서버를 통해 인증된 방식으로 접근하는 것이죠.

---

### 3️⃣ Claude Code + Remote Execution

가장 강력한 형태. Claude Code 자체를 원격 서버에서 실행하는 구조입니다.

```
CSP 모바일/다른 기기
    ↓ 명령 전송
원격 서버 (EC2, Fly.io, Railway 등)
    ↓ Claude Code 실행
    ↓ 코드 작성, 테스트, 배포
결과 → CSP에게 반환
```

CSP가 잠들어 있는 동안에도 Claude가 코드를 짜고 PR을 올리는 **비동기 AI 직원**이 가능해지는 지점입니다.

## Device Layer — 디바이스별 역할 분담

심리스한 환경의 핵심은 각 디바이스에 **명확한 역할**을 부여하는 것입니다. 세 기기가 동일한 기능을 하려 하면 오히려 혼란이 생깁니다.

**MacBook** — Deep Work Hub. Claude Code가 실행되는 유일한 디바이스. 코드 생성, 복잡한 분석, 긴 대화 세션이 여기서 이루어집니다. 자리에 앉아 집중할 때의 공간입니다.

**iPad** — Review & Edit Station. claude.ai 웹 브라우저로 접근. 이동 중 긴 문서를 검토하거나, 생성된 결과물을 편집하거나, Notion MCP로 아카이빙 작업을 할 때 최적입니다. 키보드 연결 시 MacBook에 가까운 생산성이 나옵니다.

**iPhone** — Dispatch & Monitor. 짧은 명령을 던지고 결과를 확인하는 "리모컨" 역할. Claude 앱으로 간단한 질문, 아이디어 캡처, 진행 중인 작업 상태 확인. 이동 중 "이 아이디어 Notion에 저장해줘" 같은 Dispatch 명령을 보내는 곳입니다.

---

## Sync Layer — 데이터의 중력 중심 만들기

세 기기가 같은 컨텍스트를 공유하려면 단일한 **진실의 원천(Single Source of Truth)** 이 필요합니다.

**iCloud Drive + 파일 앱**: 맥북의 작업 파일이 자동으로 아이패드·아이폰에서 열립니다. Obsidian vault를 iCloud에 두면 세 기기에서 동일한 노트 베이스에 접근 가능합니다.

**Notion MCP**: CSP의 Claude 대화 아카이빙 규칙이 여기서 작동합니다. 어느 디바이스에서 대화하든, MCP를 통해 동일한 Notion DB에 저장됩니다. 세컨브레인이 디바이스에 종속되지 않는 구조입니다.

**GitHub**: 코드 작업의 상태가 GitHub에 올라가면 맥북이 꺼져 있어도 아이패드에서 코드를 보고, iPhone에서 PR 상태를 확인할 수 있습니다.

---

## AI Layer — 진짜 "심리스"가 만들어지는 곳

**claude.ai 웹** (iPad + iPhone 주력): Remote MCP Connector들이 연결되어 있어, 어느 기기에서 접속해도 Notion·Gmail·Slack·Google Calendar에 동일하게 접근됩니다. CSP가 이미 연결해 두신 커넥터들이 여기서 진가를 발휘합니다.

**Claude Code Remote Execution**: 이것이 가장 강력한 구성입니다. 맥북에서 Claude Code를 headless 서버처럼 실행하거나, Railway/Fly.io 같은 클라우드에 Claude Code 환경을 올려두면 — iPhone에서 명령을 보내면 맥북(혹은 클라우드)에서 코드가 실행되고 결과가 돌아옵니다.

현실적인 단기 구성으로는, **맥북을 항상 깨어 있게 설정**하고 iPhone에서 SSH나 claude.ai를 통해 명령을 전달하는 방식이 가장 즉시 적용 가능합니다.

## Pattern A — 맥북을 서버로 (가장 현실적인 시작점)

핵심 원리는 단순합니다. 맥북을 끄지 않고 항상 켜둔 채, Claude Code를 tmux 세션 안에 살려두는 것입니다. iPhone에서 SSH로 접속해서 명령을 내리면, 맥북이 일을 하고 결과를 돌려줍니다.

구체적인 설정 순서는 이렇습니다.

**① Tailscale 설치** — 공유기가 달라도(카페, 집, 회사) 맥북과 iPhone이 하나의 가상 네트워크에 있는 것처럼 만들어줍니다. 포트 포워딩이나 공인 IP 없이 안전하게 연결됩니다.

```bash
# 맥북에서
brew install tailscale
sudo tailscale up

# iPhone → App Store에서 Tailscale 설치 후 동일 계정 로그인
```

**② 맥북 SSH 활성화** — 시스템 설정 → 일반 → 공유 → 원격 로그인 켜기. 이제 iPhone에서 맥북 IP로 SSH 접속이 가능합니다.

**③ tmux로 Claude Code 상주** — tmux는 터미널 세션을 백그라운드에 유지시켜주는 도구입니다. SSH 연결이 끊겨도 세션이 살아있습니다.

```bash
# 맥북에서 최초 세션 생성
tmux new -s claude-agent

# 이 안에서 Claude Code를 --print 모드로 실행
# --print는 대화형이 아닌 단발성 실행 모드
claude --print "ESCON의 Temporal Knowledge Graph 스키마 검토하고 문제점 리포트해줘"
```

**④ iPhone에서 접속** — Termius 앱(SSH 클라이언트)으로 Tailscale IP에 접속, tmux 세션에 붙습니다.

```bash
# iPhone Termius에서
ssh csp@100.x.x.x  # Tailscale 가상 IP
tmux attach -t claude-agent
```

## Pattern C — GitHub Actions (가장 강력한 비동기 패턴)

Anthropic이 공식 제공하는 `claude-code-action`을 사용하면, **GitHub 이슈나 PR에 댓글을 달면 Claude가 자동으로 코드를 작성하고 PR을 올려줍니다.** CSP가 iPhone에서 이슈 댓글을 달고 자리를 비우면, 돌아왔을 때 PR이 기다리고 있는 구조입니다.

```yaml
# .github/workflows/claude.yml
name: Claude Code Agent

on:
  issue_comment:
    types: [created]

jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@beta
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

사용법은 이슈에 댓글 하나면 됩니다.

```
@claude ESCON의 /app/api/skills/route.ts에서
Supabase 연결 오류 확인하고 수정해줘
```

Claude가 코드를 읽고, 수정하고, PR을 올리고, 댓글로 설명까지 달아줍니다.

## Cowork Dispatch — 실제로 무엇이 달라졌나

먼저 맥락을 정리해야 합니다. 앞서 이야기한 "Tailscale + tmux + SSH" 방식은 CSP가 직접 인프라를 구축하는 DIY 접근법이었습니다. 그런데 Anthropic이 지난주 Cowork에 Dispatch 기능을 공식 출시했습니다. 스마트폰에서 Claude에게 프롬프트를 보내면, Claude가 맥북에서 자율적으로 작업을 완료하는 방식입니다.

더 결정적인 것은 — Dispatch는 이제 Computer Use와 결합되어, Claude가 맥북을 직접 제어할 수 있습니다. 커넥터가 없는 앱은 화면을 보고 클릭·입력하는 방식으로 처리합니다.

즉, DIY 없이도 이미 "iPhone → 맥북 자율 실행"이 공식 작동합니다.

## DIY vs Cowork Dispatch — 무엇을 써야 하나

먼저 솔직하게 비교해야 합니다.

Cowork Dispatch는 "폰이나 데스크탑에서 Claude에게 태스크를 보내면, Claude가 Slack 커넥터, Chrome, 혹은 화면 직접 제어 중 가장 빠른 경로를 선택해 실행"합니다. 이것은 앞서 만든 Tailscale + tmux + dispatch.sh와 동일한 개념을 Anthropic이 공식화한 것입니다. 인프라 세팅 없이 바로 쓸 수 있다는 차이가 있습니다.

단 **두 방법은 사용 맥락이 다릅니다.** Cowork Dispatch는 파일·앱·브라우저 중심의 지식 작업에 최적화되어 있고, 직접 구축한 Claude Code 원격 실행은 코드 생성·터미널 명령·API 호출처럼 개발자 수준의 작업에 유리합니다. CSP처럼 두 세계를 동시에 사는 사람은 **둘을 상황에 따라 분기해서 쓰는 것**이 가장 강력한 구성입니다.

## 실전 Dispatch 레시피 — CSP 프로젝트별

**Pulse Check** — 설문 데이터가 Supabase에 쌓이는 순간 iPhone에서 한 줄을 보냅니다.

> "Pulse Check 4월 1차 응답 분석해줘. Supabase에서 데이터 당겨서 부서별 Well-Being 점수 비교하고 Notion 아카이브에 에세이 형식으로 저장해줘."

Cowork는 MCP Connector로 Supabase에 접근하고, Notion에 저장합니다. 커넥터가 없는 경우엔 Computer Use로 화면을 직접 제어합니다.

**ESCON** — Vercel 배포가 막혀 있는 상황에서 자리를 비워야 할 때.

> "ESCON GitHub 최신 로그 확인하고 Vercel 배포 오류 원인 분석해서 수정 방안 정리해줘. 완료되면 Notion에 기록해줘."

**EX Intelligence** — 매주 금요일 자동 실행으로 등록.

> 트리거: 매주 금요일 오후 5시  
> "이번 주 EX Intelligence 관련 수집 데이터 정리하고 주간보고 초안 작성. hr-workspace/ex-intelligence 폴더에 저장."

Scheduled Tasks 기능으로 "Pull my metrics from the analytics dashboard and drop them in the weekly report template every Friday" 같은 반복 작업을 한 번만 정의하면 자동 실행됩니다.

## CSP-OS와 Cowork 연동하는 핵심 설정

Cowork Projects 기능으로 파일, 지침, 태스크 컨텍스트를 하나의 워크스페이스 안에 유지할 수 있습니다. 로컬 폴더를 연결하면 Claude가 세션 간 컨텍스트를 잃지 않고 작업을 이어갑니다.

이것이 CSP-OS의 `CLAUDE.md`·Skills·[[AGENTS.md|AGENTS]] 구조와 연결되는 지점입니다. Cowork Project 폴더를 `hr-workspace`로 지정하면, 기존에 쌓아온 프롬프트 규칙·스킬·에이전트 정의가 Dispatch 명령에도 자동으로 적용됩니다. CSP가 구축해온 Ouroboros 방법론, DoD 체크포인트, PathologyDetector 같은 메타 규칙들이 Cowork 안에서도 살아 작동하는 구조가 됩니다.

## 결론: 세 기기의 최종 역할 분담

앞서 설계한 아키텍처가 Cowork Dispatch 출시로 더 단단해졌습니다.

**iPhone** — Dispatch 발신 전용. 짧은 자연어 명령 한 줄로 맥북에게 작업 위임. 이동 중 아이디어 캡처와 즉시 실행.

**iPad** — 결과 검토·편집·승인. Cowork가 생성한 초안을 Persistent Thread로 받아서 정제.

**MacBook** — 실행 엔진. Cowork Desktop이 상주하며 Dispatch 명령을 받아 자율 처리. 닫혀 있어도 Remote 세션은 Anthropic 클라우드 인프라에서 계속 실행됩니다.

Cowork Dispatch가 공식 출시된 지금, DIY 인프라를 구축했던 이유의 80%는 이미 Anthropic이 해결했습니다. 남은 20% — 코드 생성, 터미널 명령, 맞춤형 스크립트 실행 — 은 앞서 만든 Claude Code 원격 실행이 커버합니다. 두 레이어를 함께 쓰는 것이 CSP 수준의 워크플로우에서 현재 가능한 가장 강력한 구성입니다.

## 적용 순서 — 30분이면 전부 세팅

**1단계 (5분)** — 폴더 생성. `~/hr-workspace-cowork/` 아래 tree 구조 그대로 만들어줍니다.

**2단계 (10분)** — 각 `context/` 파일을 복사해서 저장. 이 세 파일이 CSP-OS의 영혼을 Cowork에 이식하는 핵심입니다.

**3단계 (5분)** — Claude Desktop → Settings → Cowork → Edit Global Instructions 에 Global Instructions 프롬프트를 붙여넣습니다.

**4단계 (5분)** — Cowork → New Project → Use existing folder → `hr-workspace-cowork/` 선택. Project 생성 시 Instructions 필드에 각 PROJECT.md의 내용을 넣으면 해당 프로젝트에서만 적용되는 컨텍스트가 활성화됩니다.

**5단계 (5분)** — Scheduled Tasks 3개 등록. `/schedule` 입력 후 붙여넣기.

## 왜 이 구조가 강력한가

기존 Cowork의 핵심 약점은 세션 간 망각이었습니다. Projects 기능으로 이제 "지난주 보고서를 기반으로 이어가줘"가 실제로 작동합니다. 여기에 CSP-OS의 `csp-profile.md` + `writing-style.md` + `ground-rules.md` 3개 파일을 더하면 — Cowork가 매 태스크마다 CSP가 누구인지, 어떻게 써야 하는지, 무엇을 절대 하면 안 되는지를 자동으로 로드합니다. 이 파일들은 시간이 지나면서 쌓이고 다듬어지며, 매 수정이 이후 모든 세션을 조금씩 더 좋게 만드는 복리 구조로 작동합니다.
