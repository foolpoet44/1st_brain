## Claude Code `/memory` 명령어 — 현재 상태

### `/memory`가 하는 일

`/memory`를 실행하면 현재 세션에 로드된 모든 CLAUDE.md와 rules 파일 목록을 보여주고, Auto Memory 켜기/끄기 토글을 제공하며, Auto Memory 폴더를 열 수 있는 링크를 제공합니다.

간단히 말해 **"내 Claude Code가 지금 뭘 기억하고 있나"를 보는 관제탑**입니다.

---

### Memory의 4계층 아키텍처

Claude Code의 메모리는 4개 레이어로 구성됩니다. Layer 1은 조직 전체에 적용되는 관리 정책, Layer 2는 개인 머신의 사용자 설정, Layer 3는 팀이 공유하는 프로젝트 지침, Layer 4는 Claude가 사용자 행동 기반으로 스스로 학습·기록하는 Auto Memory입니다.

CSP의 4-layer hr-workspace 구조(`Rules/Skills/Agents/CLAUDE.md`)와 거의 동형(同形)의 개념입니다.

---

### Auto Memory — 핵심 기능

Auto Memory는 Claude가 세션을 거치며 지식을 자동 축적하는 기능입니다. 빌드 명령어, 디버깅 인사이트, 아키텍처 노트, 코드 스타일 선호도, 워크플로우 습관 등을 스스로 저장하며, 매 세션마다 저장하는 게 아니라 "미래 대화에서 유용할지" 여부를 스스로 판단합니다. Auto Memory는 Claude Code v2.1.59 이상에서 사용 가능하고, 기본값은 ON입니다.

파일 위치는 `~/.claude/projects/<project>/memory/`이며, 모두 **plain markdown**이라 직접 편집·삭제 가능합니다.

---

### Auto Dream — 메모리 정리 시스템 (최신 기능)

Auto Dream은 Auto Memory가 축적한 내용을 검토해서, 여전히 유효한 것은 강화하고 오래된 항목은 제거하며 나머지는 깔끔한 토픽 파일로 재구성하는 REM 수면 같은 역할을 합니다. `/dream` 명령어가 존재하지만 아직 모든 사용자에게 롤아웃되지 않았으며, 그 전까지는 Claude에게 직접 "dream", "auto dream", "consolidate my memory files"라고 말하면 동일한 4단계 프로세스가 실행됩니다.

---

### CSP 실전 활용 포인트

**`#` prefix 패턴** — 즉시 메모리에 저장

어떤 지시 앞에 `#`을 붙이면 즉시 메모리에 추가됩니다. 빌드 시스템의 특이점을 발견했다면 `# NODE_ENV를 명시하지 않으면 빌드 실패`처럼 타이핑하면 Claude가 적절한 메모리 파일에 기록합니다.

**CLAUDE.md vs Auto Memory 역할 분리**

CLAUDE.md는 Claude의 행동을 가이드하고 싶을 때 사용하고, Auto Memory는 사용자의 수정 사항이나 선호도를 수동 작업 없이 Claude가 스스로 학습하게 할 때 사용합니다.

**컴팩션(compaction) 이후에도 CLAUDE.md는 완전히 살아남습니다.** `/compact` 이후에도 Claude가 디스크에서 CLAUDE.md를 다시 읽고 세션에 재주입합니다.

---

### 정리

| 명령어 | 역할 |
|---|---|
| `/memory` | 현재 로드된 메모리 파일 목록 확인 + Auto Memory 토글 |
| `/init` | 코드베이스 분석 후 초기 CLAUDE.md 생성 |
| `# [내용]` | 즉시 메모리에 한 줄 저장 |
| `"dream"` (또는 `/dream`) | 메모리 파일 정리·통합 실행 |

CSP의 Ouroboros 자기진화 방법론이랑 연결하면, Auto Memory + Auto Dream 조합이 사실상 **에이전트 레벨의 자기학습 루프**입니다. GEMINI.md나 CLAUDE.md에 전략 레이어를 명시하고, Auto Memory가 실행 레이어의 패턴을 자동 축적하는 2-tier 구조가 지금 CSP 워크스페이스에 가장 잘 맞을 것 같아요.
