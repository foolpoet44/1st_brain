# HR AI 리서치 브리프 — 2026 년 8 월 28 일

## 개요

지난 8 월 21 일 브리프 이후 공개·갱신된 자료 중 실행 설계에 추가할 가치가 있는 3 건을 선별했습니다.

**이번 주 핵심 테마**: "Agent 가 처리했다"와 "업무가 제대로 끝났다"를 구분하는 것

- 절차 준수
- 중복 실행 방지
- 직원이 체감하는 후속조치 확인

## 1. 자연어 업무지침을 단계별 입출력으로 명시하라

**자료**: Natural-Language Workflows Are Not Software Yet: Artifact-Driven Compilation for Reliable Agent Execution  
**공개**: 2026 년 8 월 21 일 · Purdue University · arXiv 프리프린트

### 새로운 근거

연구진은 자연어 업무지침을 각 단계의 **입력·출력 산출물, 검증 조건, 분기 경로**가 명시된 실행 구조로 변환하는 **Artic**을 제안했습니다.

- **11 개 도메인·488 개 벤치마크 사례**에서 원래의 텍스트 지침 대비 과제 해결률이 **28%p 높아짐**
- 단순히 지침을 더 명확하게 다시 쓰는 방식과도 비교 검증

### HR 실무 의미 — 추론

"Pulse 를 분석하고 적절한 액션을 추천하라"는 지시만으로는 다음과 같은 단계가 빠질 수 있습니다:

- 표본 확인
- 근거 연결
- 승인 대기

지난주의 '데이터 버전 고정'에 더해, **다음 단계로 넘어갈 수 있는 조건**도 시스템이 검사해야 합니다.

### 다음 행동

Pulse 파일럿의 각 단계를 **네 칸**으로 정의하세요:

| 구분 | 내용 |
|------|------|
| 필수 입력 | 해당 단계에 필요한 데이터/조건 |
| 생성 산출물 | 단계 완료 시 생성되는 결과물 |
| 통과 조건 | 다음 단계로 진행 가능한 검증 기준 |
| 실패 시 경로 | 조건 미충족 시 대체 경로 또는 중단 기준 |

**예시**: 최소 응답 기준 미충족 시 조직별 추천 생성을 차단

### 한계

- 실제 HR 운영 실험이 아닌 산업·의료 업무 벤치마크
- 절차를 충실히 따르는 것과 판단 자체가 정확한 것은 별개
- 연구에서도 판단이 어려운 일부 영역은 성능이 낮았음

## 2. 승인된 작업도 재시도하면 두 번 실행될 수 있다

**자료**: AID-Guard: Stateful Authorization for Delegated Agent Effects  
**공개**: 2026 년 8 월 21 일 · Information Engineering University · arXiv 프리프린트

### 새로운 근거

이 연구는 **실행은 성공했지만 응답이 유실된 상황**에 주목합니다.

- 실패로 오인해 재시도하면 **한 번의 승인으로 두 번의 변경**이 발생할 수 있음
- 제안 프로토콜은 실행 직전에 **승인 내용과 현재 상태를 다시 검사**
- 결과가 불확실하면 기존 실행을 **미확정 상태로 유지**
- 두 SaaS 제공자를 대상으로 한 제한된 복구·동시성 시험에서 **중복 실행이 관찰되지 않음**

### HR 실무 의미 — 추론

다음과 같은 중복 실행 리스크는 권한이 올바르게 설정되어도 발생할 수 있습니다:

- 교육 신청 중복 등록
- 온보딩 계정 중복 생성
- 안내메일 재발송

**지난주의 최소권한 설계에 실행 결과 확인과 안전한 재시도 규칙을 추가**해야 합니다.

### 다음 행동

1. **쓰기 작업에 `action_id` 와 결과 미확정 상태를 추가**하세요
2. 타임아웃이 나면 곧바로 재실행하지 말고, **대상 시스템에서 기존 작업의 성공 여부를 먼저 조회**하도록 설계합니다

### 한계

- 제한된 시험 환경의 프로토타입
- 중복 방지는 연결 대상의 **중복요청 처리·결과조회 기능**에 의존
- 모든 HRIS 에서 동일하게 보장되지 않음
- 확인 기능이 없으면 자동 재시도 대신 **수동 확인**이 필요

## 3. Pulse 의 완료 기준은 '액션 등록'이 아니라 '직원에게 변화가 보였는가'다

**자료**: The State of Employee Experience: Q1 2026 Findings  
**공개·갱신 표기**: 2026 년 8 월 25 일 · Sogolytics

### 새로운 근거

미국 정규직 근로자 대상 두 차례 조사 비교:

- **2025 년**: 1,027 명
- **2026 년 1 분기**: 1,001 명

**주요 발견**:

- 1 분기 응답자의 **10% 만** 피드백이 항상 의미 있는 변화로 이어진다고 답함
- **33%**는 가끔이라고 답함
- 의사결정 소통이 "매우 명확하다"는 응답:
  - **임원 51%**
  - **일선 직원 21%** (큰 격차)

### HR 실무 의미 — 추론

'직원 의견을 실행으로 연결해야 한다'는 기존 결론에, **실행의 가시성이 직급별로 다를 수 있다는 측정 포인트**가 추가됩니다.

- 관리자 화면의 완료율이 높아도 직원에게는 변화가 전달되지 않을 수 있음

### 다음 행동

1. **액션 테이블에 `직원에게 결과를 알린 날짜` 필드를 추가**하세요
2. 후속 Mini Pulse 에서 **"지난 의견 수렴 이후 무엇이 바뀌었는지 알고 있다"**를 측정하세요
3. 직급별 비교는 **익명성을 확보할 수 있는 집단**에서만 수행합니다

### 한계

- 8 월에 공개된 1 분기 자료 (최근 일주일의 변화가 아님)
- 벤더 주도 자기보고 조사
- 공개 페이지에서 표본 모집·가중치·동일인 추적 여부는 충분히 확인되지 않음
- **국내 조직의 기준값이나 인과효과로 해석해서는 안 됨**

## CSP 설계에 대한 추론: Pulse-to-Action 완료 조건의 3 단계 분리

Pulse-to-Action 의 완료 조건을 다음 **세 가지**로 나누는 것이 좋겠습니다:

### 1. 절차 완료 (Procedural Completion)

- **질문**: 필수 근거와 검증 조건을 충족했는가?
- **체크리스트**:
  - [ ] 각 단계의 필수 입력 데이터 존재
  - [ ] 생성 산출물이 명세대로 출력됨
  - [ ] 통과 조건 검증 로직 실행됨
  - [ ] 실패 시 경로가 명시됨

### 2. 실행 완료 (Execution Completion)

- **질문**: 승인한 조치가 중복 없이 실제 반영됐는가?
- **체크리스트**:
  - [ ] `action_id` 가 부여됨
  - [ ] 결과 미확정 상태 처리 로직 존재
  - [ ] 타임아웃 시 재조회 로직 구현
  - [ ] 대상 시스템의 중복요청 처리 기능 확인

### 3. 피드백 완료 (Feedback Completion)

- **질문**: 직원에게 결과가 전달됐고, 후속 변화가 확인됐는가?
- **체크리스트**:
  - [ ] `직원에게 결과를 알린 날짜` 기록됨
  - [ ] 후속 Mini Pulse 에서 변화 인지율 측정
  - [ ] 직급별 인식 차이 모니터링 (익명성 확보 시)
