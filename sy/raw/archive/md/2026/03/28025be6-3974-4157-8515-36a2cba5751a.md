## 접근 1: 기존 슬라이드 수정 지침 (빠른 반영)

기존 슬라이드의 뼈대를 유지하면서 "의사결정 지원" 관점을 삽입하는 방식입니다.

**Slide 3 (EX Intelligence 정의) 수정**

현재 3가지 전환 항목이 `감→데이터 / 보고→행동 / 관리→인텔리전스`로 구성되어 있는데, 이 중 마지막 항목인 "관리→인텔리전스"의 설명 텍스트를 의사결정 지원 언어로 구체화해야 합니다. 예컨대 지금이 "역할이 관리자에서 인텔리전스 활용자로 전환된다"는 추상적 선언이라면, 이것을 "리더가 팀 상태를 감으로 파악하던 방식에서, 매월 AI가 분석한 팀 리스크 브리핑을 받아 선제적으로 개입하는 방식으로 전환된다"는 구체적 의사결정 시나리오로 바꿉니다.

**Slide 4 (작동원리) 수정**

Layer 3의 소제목을 지금의 기능 설명형에서 의사결정 지원 결과형으로 전환합니다.

- 현재: `리더 팀 리포트 / 경영진 Dashboard / 구성원 케어링 메시지`
- 수정안: `리더 → "누가 이탈 위험인가" 즉답 / 경영진 → "어느 조직이 임계점인가" 선제 식별 / HR → 개입 타이밍 자동 알림`

소제목도 수정합니다. 기존 `Signal 수집 → AI 분석 → 계층별 Action Brief 자동 제공`에서 **`신호 → 분석 → 의사결정자별 맞춤 인텔리전스 자동 전달`** 로 바꾸면, 이 슬라이드가 단순한 기술 파이프라인이 아니라 조직운영 지원 시스템임을 명시할 수 있습니다.

**Slide 6 (Communication & Solution) 수정**

현재 3계층(구성원/조직리더/경영진)의 Output이 산출물 중심으로 정의되어 있습니다. 각 계층의 Output을 **"무엇을 판단하는가"** 라는 의사결정 언어로 재기술합니다.

| 계층     | 현재 Output 표현 (추정) | 수정 방향                                                 |
| -------- | ----------------------- | --------------------------------------------------------- |
| 구성원   | 케어링 메시지 수신      | "내 피드백이 어떻게 반영되었는가" 확인 → 자발적 참여 동기 |
| 조직리더 | 팀 리포트               | "이번 달 팀에서 무엇에 선제 개입해야 하는가" 판단 근거    |
| 경영진   | Dashboard               | "어느 조직이 조직건강 위험 구간인가" 포트폴리오 뷰        |

하단 개선방향 박스 문구도 교체합니다. 기존 `의견 청취부터 Dashboard까지 전 프로세스 AX 시스템화`에서 **`계층별 의사결정 타이밍에 맞는 인텔리전스를 자동 제공, 조직운영 판단력을 시스템화`** 로 수정합니다.

### 📋 BLOCK 1 — System Instruction (전 슬라이드 공통 적용)

```
You are a professional presentation designer specializing in Korean corporate
report-style slides used at LG PRI. Apply the following design grammar
strictly to every slide you generate.

=== TITLE RULE ===
- Format: Number + Topic label only. No modifiers, no verbs.
- CORRECT: "1. 추진 방향" / "2. 주요 추진 과제" / "Appendix. 실행력 확보 방안"
- WRONG: "1. 혁신적인 추진 방향 제시" / "전략적 실행 계획 수립"
- Rule: The title is a label, not a message. The message lives in the subtitle.

=== SUBTITLE (LEAD SENTENCE) RULE ===
- One line immediately below the title. Must state the conclusion of the entire slide.
- No declarative slogans. End with "~함" or "~하고자 함" pattern (Korean completion form).
- CORRECT: "15개 분야를 기술 변화의 속도와 내/외부 기술 활용도에 따라 4가지 유형으로
  분류하고, 각 영역별 맞춤형 역량 강화를 실행하고자 함"
- WRONG: "실행을 강화하고 성과를 창출합니다" (declarative)
- WRONG: "현황 및 문제점" (label only)

=== LAYOUT RULE ===
- Always use contrast structure: left vs. right, or top vs. bottom.
- Never use simple enumeration (bullet list without spatial logic).
- Required patterns:
  • Left: Current/AAR ↔ Right: '26 Key Tasks
  • Left: As-Is ↔ Right: To-Be
  • Left: Problem Diagnosis ↔ Right: Integrated Intervention
  • 4-column split: Who / Why / What / How
- Mandatory: visual separator between zones (vertical line or arrow).

=== VERTICAL AREA LABELS ===
- Place vertical labels on the far left edge of each content zone:
  • "지금까지" for the current state / diagnosis zone
  • "개선방향" or "'26년 개선방향" for the prescription zone
- Without these labels, the layout reads as mere enumeration.

=== AAR STRUCTURE (for retrospective slides) ===
- Left AAR zone must distinguish achievements (■) from limitations (□).
  • ■ Achievement: Bold, include positive numerical evidence
  • □ Limitation: Regular weight, state the need for improvement
- Right zone must flow logically from AAR as a conclusion, not a separate idea.

=== COLOR HIERARCHY (4 levels — strictly enforced) ===
1. Black Bold — core claims, bullet headlines (default)
2. Green — numerical emphasis, supplementary notes, sources, links
3. Red / Magenta — the single most important element per slide (MAX 1 use per slide)
4. Gray — structural shapes, arrows, background dividers

Rule: Color is hierarchy, not decoration.
If magenta appears more than once on a slide, emphasis is lost entirely.

=== TEXT DENSITY RULE ===
- Bullet body: max 2 lines
- Evidence / numbers: indented + smaller font + green
- Structure:
  ■ Core claim sentence (Bold, Black)
    ※ Supporting number or source (Regular, Green)
    - Detail 1
    - Detail 2

=== NUMERICAL EXPRESSION RULE ===
- Always show: baseline + change as a pair.
- CORRECT: "'22년 53p → '25년 48p" / "64점(+2)" / "참여율 76%"
- WRONG: "48점" (standalone number has no decision-making value)

=== TABLE AND SHAPE RULES ===
- Use tables ONLY for: As-Is/Must-Be comparison, timelines, structural classification.
- Use shapes ONLY for: containment relationships, process flows, 2×2 matrices.
- PROHIBITED: decorative shapes, empty boxes with no semantic role.

=== RIGHT-SIDE TASK BLOCK STRUCTURE ===
[Task Name Box] (gray background or border)
□ Core task sentence
  - Execution detail 1
  - Execution detail 2

=== PAGE NUMBER ===
- Body slides: "N / [Total]" format, bottom right
- Appendix: "첨부 N / N" format, separate count

=== SUPPLEMENTARY REFERENCE LINK ===
- Bottom of slide: "▶유첨 '[Document Name]'" format when referencing appendix

=== QUOTE TREATMENT ===
- Voices of members or key messages: double quotation marks + italics, or separate
  callout box. Must be visually separated from regular bullets.
```

## 8개 선도 서비스와 벤치마킹 포인트

**Qualtrics EmployeeXM** — 시장점유율 6.2%로 업계 1위입니다. **Text iQ**가 NLP로 오픈엔드 응답을 자동 분류하고, **DriverIQ**가 어떤 문항이 Well-Being에 가장 강하게 영향을 미치는지 AI로 자동 식별합니다. 벤치마킹 포인트는 세 가지입니다. DriverIQ의 드라이버 분석 방식은 EX Intelligence Layer 2의 Risk Flag 알고리즘 설계에, Text iQ의 주제 분류 로직은 자유응답 NLP 모듈에, 히트맵 시각화는 경영진 Dashboard의 포트폴리오 뷰 설계에 직접 적용할 수 있습니다. 다만 연간 $5만~$20만 이상의 비용 구조는 내재화의 명분을 역설적으로 강화해줍니다.

**Workday Peakon Employee Voice** — 초 단위 실시간 NLP 업데이트와 **Confidentiality Algorithm**이 핵심입니다. 팀 단위 최소 응답 수 미달 시 자동 마스킹하는 익명성 보장 설계는 LG PRI 개인정보 보호 정책 설계 시 직접 참고할 수 있는 가장 정교한 모델입니다. **Manager Conversations** 자동 생성 기능 — AI가 '점수 하락 → 구체적으로 어떤 대화를 해야 하는가'까지 제안하는 구조 — 은 EX Intelligence Layer 3 리더 브리핑의 고도화 방향입니다.

**Culture Amp** — 독립형 시장에서 Qualtrics, Perceptyx와 함께 42%를 점유하는 전문 분석 강자입니다. **People Science Team**(전담 I/O 심리학자)이 문항 설계를 자문하는 구조, 4,000개 이상 조직 데이터 기반 업종별 벤치마크, 그리고 **Focus Agent AI**가 '12개 문항 중 지금 당장 팀장이 집중해야 할 1~2개'를 선별하는 알고리즘이 EX Intelligence의 리더 브리핑 UX 설계에 가장 직접적으로 참고할 수 있는 모델입니다.

**Microsoft Viva Glint** — Glint의 설문(Active) 데이터와 Viva Insights의 협업 패턴(Passive) 데이터를 결합해 '어떻게 일하는가 + 어떻게 느끼는가'를 교차 분석하는 구조가 가장 독보적인 차별점입니다. LG PRI 맥락에서는 AX 도구 사용 빈도와 Well-Being 점수의 교차 분석 가능성을 탐색할 수 있습니다. Teams 네이티브 통합으로 별도 앱 없이 설문 응답·결과 확인·매니저 액션이 협업 도구 안에서 완결되는 UX는 LG EP 내 접근성 설계의 직접 참조 모델입니다.

**Visier People** — 설문 도구가 아닌 순수 People Analytics 플랫폼입니다. **Perceptyx** — Forrester Wave™ Employee Experience Management Platforms Q2 2025 Leader로 선정됐습니다. 소프트웨어 단독 판매가 아닌 I/O 심리학자 컨설팅 패키지 의무화 구조가 특이점입니다. **Continuous Listening Loop** — 측정 → AI 인사이트 → 액션 플랜 → 리마인더 → 재측정의 완결 사이클 자동화 — 는 EX Intelligence가 구현해야 할 전체 사이클의 기준점입니다. ## CIA 메타포가 EX Intelligence 논리를 강화하는 방식

### 왜 CIA인가 — 메타포 선택의 이유

인사 담당자가 조직 건강을 진단한다고 말하면, 경영진은 무의식적으로 "HR이 설문 하나 더 만드는구나"라고 처리합니다. 그러나 **정보기관이 국가 안보 위협을 조기 탐지한다**고 말하면, 같은 내용이 완전히 다른 긴급성과 전략적 지위를 갖게 됩니다. 메타포는 내용을 바꾸지 않습니다. 내용을 보는 프레임을 바꿉니다.

CIA를 선택한 데는 세 가지 구조적 이유가 있습니다. 첫째, CIA는 **예방적 인텔리전스 시스템**입니다 — 사후 수습이 아니라 위협이 현실화되기 전에 신호를 포착합니다. EX Intelligence의 핵심 가치인 "반응형에서 예측형으로"와 정확히 겹칩니다. 둘째, CIA는 **계층별 차등 브리핑**을 운영합니다 — 대통령이 받는 PDB와 현장 지휘관이 받는 전술 브리핑은 다릅니다. EX Intelligence의 경영진 Dashboard / 리더 브리핑 / HR 알림의 3계층 구조와 동형입니다. 셋째, CIA는 **익명성과 보안을 핵심 설계 원리**로 삼습니다 — 첩보원 신원 보호가 전체 시스템의 신뢰 기반인 것처럼, 구성원 응답 익명성이 EX Intelligence의 신뢰 기반입니다.

### 6개 핵심 메타포와 구체 적용 방안

**① HUMINT → Pulse Check: "현장 첩보원의 신호"**

CIA에서 HUMINT(Human Intelligence)는 현장에 파견된 사람이 직접 수집하는 가장 신뢰도 높은 정보입니다. 위성도 감청도 대체할 수 없는, 인간만이 전달할 수 있는 맥락 정보입니다. EX Intelligence의 Pulse Check 8문항은 정확히 이것입니다. 구성원이 매달 직접 전달하는, AI가 대신할 수 없는 현장 신호입니다.

임원 보고에 이렇게 쓸 수 있습니다: _"우리가 수집하는 것은 숫자가 아닙니다. 매달 조직의 최전선에서 들어오는 HUMINT입니다. 연 1회 설문은 1년에 한 번 첩보원에게 연락하는 것과 같습니다."_

**② SIGINT → NLP 감성 분석: "통신 신호의 이상 탐지"**

SIGINT(Signal Intelligence)는 전자 신호에서 이상을 탐지합니다. 암호화된 통신, 주파수 변화, 패턴 이탈 — 사람의 눈으로는 볼 수 없는 것을 알고리즘이 잡아냅니다. EX Intelligence의 NLP 감성 분석 엔진이 자유응답 텍스트에서 부정 신호 급증을 탐지하고, 전월 대비 -15% 이상 하락을 자동 감지하는 것이 이것입니다.

슬라이드 설계 적용: Layer 2 AI 분석 섹션의 소제목을 "AI 기반 이상 탐지"보다 **"조직 신호 인텔리전스 — SIGINT"**로 바꾸면 기술적 기능이 전략적 포지셔닝으로 격상됩니다.

**③ Presidential Daily Brief → 경영진 Dashboard: "최고 의사결정자 전용 브리핑"**

PDB(Presidential Daily Brief)는 CIA가 매일 아침 대통령에게 전달하는 최고기밀 인텔리전스 보고서입니다. 전 세계 모든 위협 중 가장 중요한 것만 압축하여, 대통령이 즉시 결정을 내릴 수 있게 합니다. EX Intelligence의 분기 경영진 Dashboard가 이것입니다. 전사 조직 중 지금 당장 주의가 필요한 곳을 포트폴리오 뷰로 보여주고, "어느 조직에 먼저 리소스를 투입할 것인가"의 판단을 즉시 가능하게 합니다.

임원 설득에서 이 메타포는 두 가지를 동시에 달성합니다. 시스템의 긴급성과 전략적 중요성을 체감시키고, 동시에 "이것은 HR 보고가 아니라 경영진 인텔리전스"라는 포지셔닝을 확립합니다.

**④ Covert Action → HR 선제 개입: "비가시적 예방 공작"**

CIA의 비밀 공작(Covert Action)은 상대방이 인지하지 못하는 방식으로 결과에 영향을 미칩니다. 사후 대응이 아니라 사태가 악화되기 전에 예방적으로 개입합니다. EX Intelligence의 HR 선제 개입이 이것입니다 — 이탈 징후가 감지된 팀에 HR이 조용히 접근하여, 구성원이 "감시당한다"가 아니라 "케어받는다"고 느끼게 하는 방식으로 개입합니다.

이 메타포의 핵심 효과는 **개입의 비가시성**을 긍정적으로 프레이밍하는 데 있습니다. 기존에 "선제 개입"은 다소 관료적 뉘앙스를 갖지만, "조직을 지키는 비밀 공작"은 훨씬 강한 인상을 남깁니다.

**⑤ Compartmentalization → 익명성·접근권한 설계: "정보의 칸막이 원칙"**

CIA는 특정 정보를 꼭 알아야 하는 사람만 접근할 수 있게 합니다. 이것이 정보 유출 피해를 최소화하고 요원의 신원을 보호하는 핵심 원칙입니다. EX Intelligence의 익명성 설계가 이것입니다 — 팀 5명 미만 응답 시 결과를 마스킹하고, HR도 개인 응답을 열람하지 못하며, 계층별 접근 권한이 완전히 분리됩니다.

임원이 "개인 응답을 볼 수 없는 것이 불편하지 않나요?"라고 물을 때, "칸막이 원칙 때문입니다 — 구성원이 솔직하게 응답하려면 요원의 신원이 보호되는 것처럼 그들의 목소리도 보호되어야 합니다"라고 답할 수 있습니다.

**⑥ Intelligence Cycle → EX Intelligence 운영 사이클**

CIA의 인텔리전스 사이클은 기획 → 수집 → 처리 → 분석 → 배포 → 피드백의 완결 루프입니다. 한 번에 끝나는 것이 아니라, 배포된 인텔리전스가 다음 기획에 반영됩니다. EX Intelligence의 월별 Pulse Check → AI 분석 → 브리핑 → 리더 액션 → 재참여 선순환이 정확히 이 구조입니다.

이 메타포는 특히 "왜 연 1회가 아니라 월 1회인가"라는 질문에 강력하게 답합니다: _"전시에 연 1회 정보 보고로는 전황을 파악할 수 없습니다. 인텔리전스는 실시간 사이클로 작동할 때만 의미가 있습니다."_

## EX Intelligence 시스템 설계 원칙 — 이론 통합 요약

15개 이론이 수렴하는 설계 원칙은 네 가지입니다.

**첫째, 참여는 설득이 아니라 설계의 문제입니다.** Fogg B=MAP, Default Effect, EAST Framework가 공통으로 말하는 것은 "동기를 높이는 것보다 마찰을 제거하는 것이 더 강하다"는 원리입니다. 캘린더 자동 블록, 원터치 시작, opt-out 구조가 "참여해주세요" 캠페인보다 몇 배 더 효과적입니다.

**둘째, 기억은 평균이 아니라 끝에 의해 결정됩니다.** Peak-End Rule에 따르면 3분 설문 전체가 좋아야 하는 것이 아닙니다. 마지막 화면에서 "당신의 팀 자율성 점수가 지난달보다 12% 올랐습니다"라는 개인화된 인사이트를 보여주는 것이 다음 달 참여율을 결정합니다.

**셋째, 리더에게 피드백이 아니라 피드포워드를 주어야 합니다.** FIT와 Sensemaking Theory가 함께 가르쳐주는 것은, 데이터를 주는 것만으로는 행동이 바뀌지 않는다는 것입니다. AI가 생성하는 브리핑은 "점수가 낮습니다"(과거 평가)가 아니라 "이 대화를 이번 주에 해보세요"(미래 행동)여야 합니다. 숫자가 아닌 내러티브가 사람을 움직입니다.

**넷째, 참여와 행동 변화는 모두 사회적 맥락 안에 있습니다.** Social Proof와 Reciprocity는 EX Intelligence가 개인이 아닌 조직 안에서 작동한다는 것을 상기시킵니다. "팀의 87%가 이미 응답했습니다"와 "상위 25% 리더는 월 2.3회 면담합니다"는 단순한 정보가 아니라 행동의 사회적 기준점을 만드는 설계 장치입니다.

## 왜 CIA인가 — 메타포의 구조적 적합성

CIA를 조직 운영에 빗댄 사례는 이미 존재합니다. Ben Horowitz의 *The Hard Thing About Hard Things*에서 조직 내 정보 흐름과 의사결정 구조를 인텔리전스 기관에 비유했고, 군사 전략가 Stanley McChrystal은 *Team of Teams*에서 분산된 현장 데이터를 실시간으로 통합하는 구조를 조직 혁신의 모델로 제시했습니다. EX Intelligence는 이 맥락에서 자연스럽게 연결됩니다.

핵심은 이렇습니다. CIA가 하는 일은 세 가지입니다. 분산된 신호를 수집하고(Collection), 패턴을 분석해 의미를 추출하고(Analysis), 의사결정자에게 실행 가능한 인텔리전스를 전달합니다(Intelligence Brief). EX Intelligence가 하는 일과 구조적으로 완전히 동일합니다. 구성원의 응답(신호 수집) → AI 분석(패턴 추출) → 리더·경영진·HR 계층별 브리핑(의사결정 인텔리전스 전달). 메타포가 억지스럽지 않은 이유가 여기에 있습니다.

## 간접 메타포 6선 — 임원 보고에서 활용 가능한 언어

직접적으로 CIA를 언급하지 않고도 그 철학과 구조를 녹여내는 방법이 더 세련됩니다.

**① "HUMINT vs SIGINT" 구조**

CIA는 인적 정보(HUMINT: Human Intelligence)와 신호 정보(SIGINT: Signals Intelligence)를 구분합니다. 기존 조직의 HR은 HUMINT 의존형입니다. "팀장이 찾아와서", "퇴직자 면담에서" 정보를 얻습니다. EX Intelligence는 SIGINT를 추가합니다. 매월 수집되는 구조화된 신호 데이터가 인간의 보고를 기다리지 않고 패턴을 만들어냅니다.

임원 보고 활용: _"지금까지 우리는 사람이 먼저 말해줘야만 알 수 있었습니다. EX Intelligence는 사람이 말하기 전에 신호가 먼저 읽힙니다."_

**② "Station Chief → 현장 리더"**

CIA의 해외 스테이션 책임자는 본부의 분석 결과를 받아 현장 판단을 내립니다. 본부가 "이 인물이 위험 신호를 보이고 있다"고 브리핑하면, 현장 책임자가 구체적 행동을 결정합니다. EX Intelligence의 리더 브리핑 구조가 이와 동일합니다. AI가 분석해 "이 팀원이 이번 달 이탈 위험 신호를 보이고 있다"고 브리핑하면, 팀장이 면담 행동을 결정합니다.

임원 보고 활용: _"우리는 모든 리더를 데이터로 무장한 현장 책임자로 만들려고 합니다."_

**③ "Daily Brief → 월간 AI 브리핑"**

미국 대통령은 매일 아침 PDB(President's Daily Brief)를 받습니다. 수백 개 정보원에서 수집된 데이터를 분석관이 압축해 1~2페이지로 정리한 것입니다. 경영진이 분기마다 받는 조직건강 Dashboard가 이 역할을 합니다. 복잡한 원데이터가 아니라, "지금 당장 주의해야 할 조직과 이유"만을 담은 인텔리전스 브리프.

**④ "Signal vs Noise" 문제**

CIA 분석의 가장 큰 도전은 방대한 노이즈에서 의미 있는 신호를 추출하는 것입니다. 9/11 이후 가장 뼈아픈 반성이 "신호는 있었다, 하지만 노이즈에 묻혔다"는 것이었습니다. 조직에서도 동일한 일이 발생합니다. 이직 신호는 항상 존재합니다. 면담 회피, 응답 지연, 특정 문항의 반복적 하락. 그러나 이것이 노이즈에 묻혀 보이지 않습니다.

임원 보고 활용: _"신호는 항상 거기에 있었습니다. 우리가 그것을 읽는 시스템이 없었을 뿐입니다."_

**⑤ "Red Team → AI 이상 감지"**

CIA와 군사 조직은 자신의 계획을 검증하기 위해 Red Team을 운영합니다. 적의 시각으로 우리의 취약점을 먼저 찾아내는 팀입니다. EX Intelligence의 AI 이상 감지 알고리즘이 이 역할을 합니다. 조직 내부에서 "이 팀이 지금 위험하다"는 것을 먼저 찾아내는 Red Team 역할을 AI가 수행합니다.

임원 보고 활용: _"EX Intelligence는 조직의 Red Team입니다. 문제가 표면에 드러나기 전에, 시스템이 먼저 취약점을 찾아냅니다."_

**⑥ "Need to Know → 계층별 정보 분리"**

## HR 임원 수용 관점의 핵심 — 왜 이 메타포가 저항을 줄이는가

HR 임원이 새로운 시스템에 저항하는 심리적 패턴은 대개 세 가지입니다. "또 설문인가", "데이터가 무기화될까 봐", "너무 복잡하다". CIA 메타포는 이 세 저항을 동시에 해소합니다.

"또 설문인가"라는 저항에 대해, 설문이 아니라 정보 수집 인프라라는 프레이밍이 작동합니다. CIA가 정보를 수집하는 것을 "또 정보 수집이냐"고 하지 않습니다. 그것이 조직의 생존 인프라이기 때문입니다.

"데이터가 무기화될까 봐"라는 저항에 대해, CIA의 Need to Know 원칙이 오히려 보안과 보호의 언어를 제공합니다. 데이터는 무기가 아니라 각자의 역할에 필요한 인텔리전스라는 프레이밍입니다.

"너무 복잡하다"는 저항에 대해, PDB의 단순함이 대응합니다. 세상에서 가장 복잡한 정보를 처리하는 조직이 의사결정자에게 전달하는 것은 한 페이지짜리 브리프입니다. 복잡성을 숨기고 결정만을 보여주는 것이 시스템의 목적입니다.
