## Claude Code + Qwen 연결: 경제성 기반 모델 선택 가이드

### 왜 연속 코딩에서 토큰 비용이 폭발하는가

연속 코딩 세션의 핵심 문제는 **컨텍스트 누적**입니다. Claude Code는 매 턴마다 전체 대화 히스토리를 재전송하기 때문에, 채팅봇이 "기억"을 유지하려면 매 메시지마다 전체 대화 히스토리를 재전송해야 하고, 이 때문에 입력 토큰 사용량이 매 턴마다 증가한다. 결국 **입력 가격이 총 비용의 핵심 변수**가 됩니다.

### 추천 3단계 전략

**🥇 1순위: Qwen3-Coder (via Alibaba DashScope) — CSP 환경 Best Fit**

Qwen3-Coder-480B-A35B-Instruct는 오픈 모델 중 Agentic Coding, Agentic Browser-Use, Agentic Tool-Use에서 최고 수준의 결과를 달성했으며, Claude Sonnet 4와 비교 가능한 성능을 보인다. 그리고 결정적으로, Claude Code를 포함한 대부분의 플랫폼을 지원하며, 특별히 설계된 함수 호출 포맷을 갖추고 있고, 레포지토리 규모 이해에 최적화된 256K 네이티브 컨텍스트를 지원한다.

ESCON, Pulse Check 같은 실제 프로젝트 코드베이스를 다루는 CSP의 작업 패턴에는 긴 컨텍스트가 필수적이라 이 모델이 이상적입니다.

**🥈 2순위: Qwen-Flash — 순수 비용 최소화**

Qwen-Turbo(Flash 전신)는 1M 컨텍스트로 $0.065/$0.26 수준이며, 단순 반복 작업, 보일러플레이트 코드 생성, CSS/HTML 수정 등 "고민 없는 코딩"에 적합합니다. Alibaba는 Qwen-Turbo 대신 Qwen-Flash를 권장하고 있으며, Batch Invocation을 지원하는 모델은 실시간 추론 가격의 50%로 청구된다.

**🥉 3순위: Qwen3-Coder-Next (로컬 자가 서빙) — 제로 비용 옵션**

Qwen3-Coder-Next는 80B 총 파라미터 중 3B만 활성화되어, 10~20배 더 많은 활성 파라미터를 가진 모델과 비슷한 성능을 달성하며 에이전트 배포에 매우 비용 효율적이다. Claude Code를 llama.cpp를 통해 로컬 모델에 연결하면 API 요금 없이 완전한 에이전트 코딩 설정을 구동할 수 있다. 단, M-series Mac이나 GPU가 필요합니다.

### Claude Code에 Qwen 연결하는 방법

**DashScope 클라우드 연결 (가장 간단)**:

```bash
# Claude Code settings.json에 추가
export ANTHROPIC_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
export ANTHROPIC_API_KEY=sk-your-dashscope-key

# 또는 claude code 실행 시
claude --model qwen3-coder-480b-a35b-instruct
```

**OpenRouter 경유 (멀티 모델 스위칭)**: OpenRouter를 proxy로 두면 Claude Code 안에서 Qwen-Flash ↔ Qwen3-Coder를 작업 성격에 따라 쉽게 전환 가능합니다.

### CSP에게 실질적인 의미

연속 코딩에서 **"싼 게 비지떡"이 되는 임계점**이 있습니다. Qwen-Flash는 단순 작업에선 극강의 경제성이지만, ESCON의 Supabase 스키마 설계나 EX Intelligence 에이전트 아키텍처 같은 복잡한 멀티파일 작업에서는 오류 수정 토큰이 오히려 더 많이 발생합니다.

실용적 권고는 **Qwen3-Coder를 주력**, **Qwen-Flash를 반복 작업 보조**로 사용하는 투트랙입니다. Alibaba의 Coding Plan을 통하면 별도 코딩 플랜 엔드포인트(`coding.dashscope.aliyuncs.com/v1`)를 통해 qwen3.6-plus 등 모델을 더 유리한 조건으로 사용할 수 있다.

가장 지적으로 흥미로운 선택지는 Qwen3-Coder-Next 로컬 서빙입니다 — 비용이 문자 그대로 $0이 되고, 데이터가 외부로 나가지 않으며, CSP의 "SaaS 창업 proof-of-concept" 관점에서도 인프라 역량 검증이 됩니다. 단, 하드웨어 조건 확인이 먼저입니다.

## 방법 A: OpenRouter 직접 연결 ⭐ 최단경로

OpenRouter는 Anthropic Messages API와 호환되는 인터페이스를 제공하며, `ANTHROPIC_BASE_URL`을 `https://openrouter.ai/api`로 설정하면 Claude Code가 네이티브 프로토콜로 직접 OpenRouter에 연결된다. 로컬 프록시 서버가 필요 없다.

**Step 1: OpenRouter API 키 발급**

```
https://openrouter.ai → 회원가입 → API Keys → 키 생성
```

> 💡 무료 모델 일일 요청 제한 해제 팁: OpenRouter 계정에 $10를 예치하면 무료 모델 요청 한도가 기본 200회 → 1,000회/일로 확장된다. 잔액은 무료 모델 요청에 소진되지 않고 그대로 유지된다.

**Step 2: 환경변수 설정**

```bash
# ~/.zshrc 또는 ~/.bashrc에 추가
export ANTHROPIC_BASE_URL="https://openrouter.ai/api"
export ANTHROPIC_AUTH_TOKEN="sk-or-your-openrouter-key"
export ANTHROPIC_MODEL="qwen/qwen3-coder:free"
export ANTHROPIC_SMALL_FAST_MODEL="qwen/qwen3-coder:free"

# 적용
source ~/.zshrc
```

**Step 3: 기존 Anthropic 로그인 해제 후 실행**

```bash
# Claude Code 내에서
/logout

# 재시작
claude
```

**Step 4: 연결 확인**

```bash
/status    # OpenRouter 연결 확인
/model     # 현재 모델 확인
```

## 방법 B: LiteLLM 프록시 경유 (안정성 우선)

LiteLLM을 로컬에서 실행하여 Claude Code가 `http://localhost:4000`으로 요청을 보내고, 이를 OpenRouter의 Qwen3-Coder로 라우팅하는 구조다.

**Step 1: LiteLLM 디렉토리 설정**

```bash
mkdir -p ~/litellm && cd ~/litellm
```

**Step 2: config.yaml 생성**

```yaml
# ~/litellm/config.yaml
model_list:
  - model_name: "anthropic/*"
    litellm_params:
      model: "openrouter/qwen/qwen3-coder:free"
      max_tokens: 65536
      repetition_penalty: 1.05
      temperature: 0.7
      top_k: 20
      top_p: 0.8
```

**Step 3: docker-compose.yml 생성**

```yaml
# ~/litellm/docker-compose.yml
services:
  litellm:
    image: ghcr.io/berriai/litellm:main-latest
    ports:
      - "4000:4000"
    volumes:
      - ./config.yaml:/app/config.yaml
    environment:
      - OPENROUTER_API_KEY=${OPENROUTER_API_KEY}
    command: --config /app/config.yaml --port 4000
```

**Step 4: 프록시 실행**

```bash
export OPENROUTER_API_KEY="sk-or-your-key"
docker compose up -d
```

**Step 5: Claude Code 환경변수 설정**

```bash
# ~/.zshrc에 추가
export ANTHROPIC_AUTH_TOKEN="sk-1234"   # 임의 값 OK
export ANTHROPIC_BASE_URL="http://localhost:4000"
export ANTHROPIC_MODEL="openrouter/qwen/qwen3-coder"
export ANTHROPIC_SMALL_FAST_MODEL="openrouter/qwen/qwen3-coder"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1  # 텔레메트리 비활성화

source ~/.zshrc && claude
```

**편의 alias 추가 (선택)**

```bash
# ~/.zshrc
alias qlaude='ANTHROPIC_AUTH_TOKEN=sk-1234 \
  ANTHROPIC_BASE_URL=http://localhost:4000 \
  ANTHROPIC_MODEL=openrouter/qwen/qwen3-coder \
  claude'
```

## 방법 C: Claude Code Router (멀티모델 라우팅)

Claude Code Router를 사용하면 `qwen/qwen3-coder:free`와 다른 모델을 동시에 등록하고, `/model` 명령으로 세션 중에 동적으로 전환할 수 있다.

```bash
# 설치
npm install -g @musistudio/claude-code-router

# config.json 설정 (~/.claude-code-router/config.json)
```

```json
{
  "Providers": [
    {
      "name": "openrouter",
      "api_base_url": "https://openrouter.ai/api/v1/chat/completions",
      "api_key": "${OPENROUTER_API_KEY}",
      "models": ["qwen/qwen3-coder:free", "qwen/qwen3-coder-next"],
      "transformer": { "use": ["openrouter"] }
    }
  ]
}
```

```bash
# 라우터 시작
ccr start

# Claude Code에서 모델 전환
/model openrouter,qwen/qwen3-coder:free
```

## ⚠️ 알려진 이슈 & 해결법

cache_control 관련 오류 `No endpoints found that support cache control`가 발생할 수 있다. 이는 무료 티어에서 프리픽스 캐싱이 지원되지 않기 때문으로, LiteLLM config에 `cache_control: false` 옵션을 추가하거나 방법 A (직접 연결)로 전환하면 해결됩니다.

## 문제 진단

```
⚠ Auth conflict: Both a token (claude.ai) AND an API key (ANTHROPIC_API_KEY) are set
```

Claude.ai 로그인 토큰 + `ANTHROPIC_API_KEY` 가 **동시에 활성화**되어 있어서, OpenRouter로 라우팅이 안 되고 Anthropic으로 요청이 가고 있는 상태입니다. `qwen/qwen3-coder:free`는 Anthropic 서버에 없으니 "모델 없음" 에러가 발생하는 것입니다.

### Step 1: Claude.ai 로그아웃

```bash

```

> 프롬프트에서 **"API key 사용할 건가요?"** 물어보면 → `No` 선택

### Step 2: 기존 환경변수 충돌 제거

```bash
# 현재 세션에서 즉시 제거

# .zshrc에서도 제거 (중복 방지)
# ANTHROPIC_API_KEY 라인을 삭제하고 아래처럼 재설정
```

### Step 3: `.zshrc` 올바른 설정으로 교체
