# 스킬: Generate LinkedIn (링크드인 포스트 생성)

> `wiki/`, `projects/`, `outputs/` 의 내용을 기반으로 링크드인 공유용 포스트 초안을 생성합니다.

---

## 언제 쓰는가

- 프로젝트 마일스톤 달성 시
- 주간 학습 내용을 공유하고 싶을 때
- 새로 발견한 인사이트를 커뮤니티와 나누고 싶을 때
- `sharing/` 폴더에 공개용 콘텐츠를 쌓을 때

---

## 실행 단계

### 1. 소스 콘텐츠 스캔

다음 폴더를 스캔하여 공유할 거리 발굴:

- `projects/*/` — 프로젝트 진행 상황, Compiled Truth 변경사항
- `wiki/concepts/` — 새로 추가된 개념 문서
- `wiki/signals/` — 트렌드, 약한 신호 관찰
- `outputs/` — 완성된 분석 리포트, 에세이 초안
- `weekly/` — 주간 다이제스트

### 2. 콘텐츠 유형 판별

발견된 내용을 기반으로 적절한 포스트 유형 선택:

| 유형                  | 특징                        | 길이        |
| :-------------------- | :-------------------------- | :---------- |
| **인사이트 공유**     | 새로 배운 것, 깨달음        | 300~500 자  |
| **프로젝트 업데이트** | 진행 상황, 기술 도전과 해결 | 500~800 자  |
| **튜토리얼/하우투**   | 단계별 설명, 코드 스니펫    | 800~1200 자 |
| **질문/토론**         | 커뮤니티 의견 구하기        | 200~400 자  |
| **큐레이션**          | 여러 소스 종합 + 코멘트     | 500~700 자  |

### 3. 포스트 초안 생성

다음 구조로 작성:

```markdown
## [훅 - 주목을 끄는 첫 문장]

[본문 - 배운 것, 경험, 인사이트]

## 핵심 교훈

- [키 포인트 1]
- [키 포인트 2]
- [키 포인트 3]

## 관련 링크

- [GitHub 레포지토리]
- [상세 문서 링크]

#해시태그 #관련분야 #기술명
```

### 4. 출력

`sharing/linkedin/` 폴더에 저장:

- 파일명: `linkedin-[YYYY-MM-DD]-[주제].md`

---

## 작성 규칙

1. **훅 (Hook)**: 첫 2 줄에서 주목을 끌어야 함 (질문, 놀라운 사실, 공감 포인트)
2. **간결한 문단**: 한 문단 3~4 줄 이내, 가독성 우선
3. **구체적 숫자**: "많이" → "294 개 파일", "빨리" → "60% 단축"
4. **한국어 + 영어 병기**: 해시태그와 기술 용어는 영어
5. **과시 금지**: "내가 했다"보다 "배운 것"에 초점
6. **콜투액션**: 마지막에 질문이나 의견 유도 문장 추가

## 예시 프롬프트

```
generate-linkedin

이번 주 프로젝트에서 발견한 인사이트를 링크드인 포스트로 만들어줘.
주제: Graph RAG 구조와 csp-brain 위키 시스템의 유사성
톤: 전문적이되 친근하게
길이: 500 자 내외
```

## 출력 예시

```markdown
## 당신의 지식 관리 시스템, Graph RAG 와 닮았습니다

최근 csp-brain 프로젝트를 구축하면서 발견한 흥미로운 사실:
제가 운영하는 Obsidian 위키가 엔터프라이즈 Graph RAG 아키텍처와
거의 동일한 구조로 작동한다는 점이었습니다.

### 발견한 유사점

1. **엔티티 = 문서**, **에지 = 백링크**
   - 각 wiki 문서는 노드로, [[백링크]]는 관계로 작동
   - Multi-hop 추론이 자연스럽게 가능

2. **Compiled Truth = 캐시된 응답**
   - 프로젝트별 요약은 자주 조회되는 쿼리 결과물
   - Timeline = append-only 증거 로그

3. **inbox → wiki 파이프라인 = ETL**
   - 미가공 데이터가 정리된 지식으로 변환

### 인사이트

"엔터프라이즈 RAG 를 따로 구축할 필요가 없습니다.
이미 Obsidian 으로 실천하고 있다면요."

별도의 Graph DB 없이도, 백링크 2 개 이상 규칙과
wiki 폴더 구조만으로도 충분한 Graph RAG 가 됩니다.

### 다음 실험

- 백링크 0 인 고립 문서 자동 감지
- Graph View 로 지식 군집 시각화
- Claude Code 가 추천하는 연결 경로

---

#KnowledgeGraph #GraphRAG #Obsidian #ClaudeCode #SecondBrain #지식관리 #인공지능 #생산성

이런 접근법, 어떻게 보시나요? 비슷한 시도 해보신 분 계신가요? 👇
```

## 관련 스킬

- `dream-cycle` — 주간 정리 후 생성된 콘텐츠 활용
- `publish` — 생성된 포스트를 외부에 배포 (추구현)

---

## 메모

- 생성된 초안은 반드시 사람이 검토 후 게시
- 링크드인 알고리즘: 아침 8-9 시, 점심 12-1 시, 저녁 7-8 시 게시 권장
- 이미지/스킨샷 포함 시 참여율 2 배 증가
