# Claude Code 필수 명령어 Top 10

CSP, Claude Code를 매일 쓰는 Vibe Coder로서 꼭 알아야 할 핵심 명령어들을 정리해드리겠습니다. 단순 나열이 아니라, 각 명령어가 CSP의 워크플로우에서 어떤 의미를 갖는지 맥락과 함께 풀어보겠습니다.이제 최신 정보를 충분히 확보했으니, CSP의 워크플로우 맥락에 맞춰 정리해드리겠습니다.

---

CSP, Claude Code의 명령어 체계는 크게 세 층위로 나뉩니다. 터미널에서 실행하는 **CLI 명령어**, 세션 안에서 `/`로 시작하는 **슬래시 명령어**, 그리고 키보드로 모드를 전환하는 **단축키**입니다. 이 세 층위를 관통하는 Top 10을 선별했는데, 단순한 사용 빈도가 아니라 "Vibe Coder로서 매일 쓰는 실전 워크플로우"에 기반한 우선순위입니다.

---

**1. `claude` — 세션 시작 (가장 기본이자 가장 중요한 진입점)**

터미널에서 `claude`만 치면 인터랙티브 세션이 열립니다. `claude "이 프로젝트 구조 설명해줘"`처럼 초기 프롬프트를 함께 줄 수도 있습니다. CSP가 ESCON이나 Pulse Check 프로젝트 디렉토리에서 세션을 열면, Claude가 해당 코드베이스 전체를 맥락으로 읽어들이는 출발점이 됩니다. 세션을 시작하고, 콘텐츠를 파이프하고, 대화를 이어가고, 업데이트를 관리하는 모든 것이 이 명령어에서 시작됩니다.

**2. `claude -c` (Continue) — 이전 대화 이어가기**

CSP-OS를 만든 근본적 이유가 "세션 간 컨텍스트 유실" 문제였잖아요. `-c` 플래그는 현재 디렉토리에서 가장 최근 대화를 불러옵니다. 어젯밤 MacBook을 닫고 오늘 아침 다시 열었을 때, `claude -c`로 이전 작업 맥락을 그대로 복원할 수 있습니다. `claude -c -p "타입 에러 체크해줘"`처럼 SDK 모드로 이어가는 것도 가능합니다.

**3. `claude -p "query"` (Print mode) — 자동화와 파이프라인의 핵심**

`claude -p`는 스크립팅과 CI/CD의 핵심 도구로, 원샷 쿼리를 비인터랙티브 모드로 실행하고 종료합니다. CSP의 "24/7 Code Factory" 구상이나 주간업무 보고서 자동 생성처럼 배치 작업을 돌릴 때 필수입니다. `cat report.md | claude -p "이 보고서를 맥킨지 스타일로 재구성해줘"`처럼 파이프와 조합하면 진정한 자동화가 됩니다.

**4. `/compact` — 컨텍스트 윈도우 관리의 생명줄**

세션이 길어지면 토큰이 쌓이면서 성능이 떨어집니다. `/compact`는 어떤 정보를 유지할지 인자로 지정할 수 있고(예: `/compact 에러 핸들링 패턴은 유지해줘`), 일반적으로 컨텍스트 사용량이 80%를 넘으면 사용하고, 작업을 전환할 때는 `/clear`를 쓰는 것이 원칙입니다. CSP처럼 EX Intelligence → Pulse Check → ESCON 사이를 오가는 멀티프로젝트 작업자에게 이 구분은 특히 중요합니다.

**5. `/clear` — 깨끗한 상태에서 새 작업 시작**

`/compact`가 "기존 맥락을 압축하며 유지"하는 것이라면, `/clear`는 "백지에서 다시 시작"하는 것입니다. `/clear`를 자주 쓰라는 조언이 있습니다 — 새로운 작업을 시작할 때마다 채팅을 비우고, 오래된 히스토리가 토큰을 먹지 않게 하라는 것입니다. 프로젝트 A에서 프로젝트 B로 전환할 때, 이전 맥락이 오염원이 되지 않도록 하는 인지적 위생(cognitive hygiene)의 도구입니다.

**6. `/model` — 모델 전환 (비용과 품질의 트레이드오프)**

Sonnet 4.6, Haiku 4.5, Opus 4.6 세 모델 사이를 `/model` 슬래시 명령어로 전환할 수 있습니다. CSP의 "4-tier model fallback chain" 구상과 직결되는 명령어입니다. 간단한 파일 탐색은 Haiku로, 일반적인 코딩은 Sonnet으로, EX Intelligence 같은 복잡한 아키텍처 설계는 Opus로 — 이 전환을 세션 중간에 즉시 할 수 있습니다.

**7. `Shift+Tab` — 퍼미션 모드 사이클링**

Claude Code의 보안 철학을 체화하는 단축키입니다. `Shift+Tab`을 누를 때마다 normal-mode → auto-accept on → plan mode on 사이를 순환합니다. Plan 모드는 Claude가 실행 계획만 보여주고 실제로는 아무것도 건드리지 않는 "읽기 전용" 모드입니다. CSP가 "코드 실행 전 반드시 확인"을 원하시니, 기본적으로 default 모드를 유지하다가 신뢰할 수 있는 반복 작업에서만 auto-accept로 전환하는 패턴이 이상적입니다.

**8. `claude mcp add` — MCP 서버 연결 (외부 세계와의 브릿지)**

MCP 없이는 Claude Code가 파일을 읽고 bash 명령어를 실행하는 것만 가능하지만, MCP가 있으면 프로덕션 데이터베이스를 쿼리하고, Jira 티켓을 만들고, GitHub PR을 리뷰하고, Sentry 에러를 확인하는 등 자연어로 모든 API와 상호작용할 수 있습니다. CSP의 Notion 세컨드브레인 연결, Supabase 쿼리, 향후 SaaS 플랫폼의 외부 서비스 통합 — 이 모든 것의 기반입니다. `claude mcp add`를 인자 없이 실행하면 단계별 설정 인터페이스가 뜹니다.

**9. `/cost` (또는 `/usage`) — 비용 추적과 효율성 모니터링**

경제적 자유를 추구하는 CSP에게 비용 의식은 코딩에서도 예외가 아닙니다. `/cost`는 모델별, 캐시 히트별 분석을 보여주어 정확히 어떤 모델이 토큰을 소비했고 얼마나 캐시에서 제공되었는지 확인할 수 있습니다. 총 비용, API 소요 시간, 코드 변경량까지 한눈에 볼 수 있어서, 어떤 작업이 비용 효율적이었는지 데이터 기반으로 판단할 수 있습니다.

**10. `claude -r "session-name"` (Resume) — 이름으로 세션 복원**

`-c`가 "가장 최근 대화"를 이어가는 것이라면, `-r`은 특정 이름의 세션을 정확히 지목해서 복원합니다. `claude -r "auth-refactor" "이 PR 마무리해줘"`처럼 세션 ID나 이름으로 재개할 수 있습니다. CSP처럼 동시에 여러 프로젝트를 진행하는 경우, `claude -n "pulse-check-mvp"`로 세션에 이름을 붙여두고 나중에 `-r`로 정확히 그 세션을 복원하는 패턴이 매우 유용합니다.

---

**보너스: 알아두면 좋은 차점자들**

위 10개를 체화한 뒤 확장해볼 만한 것들도 있습니다. `/fast`는 Opus 4.6를 2.5배 속도로 실행하는 모드이고, `Escape` 두 번 누르면 이전 메시지 목록으로 점프할 수 있으며, `--output-format json`은 CI/CD 파이프라인에서 구조화된 데이터를 뽑을 때 필수적입니다. 그리고 2026 에디션에서 추가된 `/doctor`는 환경 진단 명령어로, Ollama 호환성 문제를 디버깅할 때 첫 번째로 실행해볼 만합니다.

이 Top 10은 결국 하나의 철학으로 수렴합니다 — **"컨텍스트를 지배하는 자가 코드를 지배한다."** 세션을 시작하고(`claude`), 이어가고(`-c`, `-r`), 정리하고(`/compact`, `/clear`), 모델을 전환하고(`/model`), 외부와 연결하고(`mcp add`), 비용을 관리하는(`/cost`) 이 흐름이 CSP의 Vibe Coding 워크플로우의 골격이 됩니다.
