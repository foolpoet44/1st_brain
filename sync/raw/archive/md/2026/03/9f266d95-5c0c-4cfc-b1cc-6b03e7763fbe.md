## 젠스파크 AI Slides — 서비스 해부와 에이전트 재현 가능성 분석

젠스파크가 슬라이드 생성에서 높은 만족도를 주는 이유는 단순히 "PPT를 잘 만든다"가 아닙니다. 그것은 **리서치 → 구조화 → 디자인 렌더링 → 사실검증 → 내보내기**라는 파이프라인 전체를 단일 프롬프트 안에서 끊김 없이 처리하기 때문입니다. 이것은 툴의 문제가 아니라 아키텍처의 문제입니다.

---

### 1. 젠스파크 AI Slides의 핵심 특성 레이어

먼저 젠스파크가 실제로 무엇을 하고 있는지를 레이어별로 분해해야 합니다.

**① Orchestration Layer (슈퍼 에이전트)**

젠스파크의 Super Agent는 프롬프트를 받으면 적합한 도구들을 선택하고, 필요하면 웹 검색, 복수의 AI 모델 실행, 답변 비교 과정을 거쳐 리포트, 덱, 테이블을 완성한다. 핵심은 사용자가 하나의 프롬프트를 던지면, 내부에서 **리서치 에이전트, 구조화 에이전트, 렌더링 에이전트가 분업**한다는 것입니다.

**② Content Generation Layer (세 가지 모드)**

Guide Mode는 단계별 컨설테이션 방식으로 청중, 목적, 콘텐츠 소스, 내러티브 구조, 디자인 선호를 명확히 한 뒤 슬라이드를 생성한다. Creative Mode는 불릿 포인트 대신 스토리텔링으로 아이디어를 시각적 관계로 구성하며 각 슬라이드를 포스터처럼 완결된 비주얼로 설계한다. Professional Mode는 데이터 중심 보고서, 공식 피치덱, 구조적 비즈니스 문서에 최적화된 클래식 방식이다.

**③ Design Rendering Layer**

스마트 레이아웃 & 디자인 기능은 깔끔한 레이아웃, 브랜드 스타일, 시각적으로 매력적인 템플릿으로 슬라이드를 자동 포맷하고, 파일에서 핵심 인사이트를 추출해 신뢰할 수 있는 소스로 빈 내용을 채운다.

**④ Quality Assurance Layer**

팩트체크 옵션은 버튼 하나로 각 슬라이드에 대한 팩트체크 프롬프트를 생성하고, 어떤 주장에 강력한 출처가 있는지, 어떤 데이터가 더 나은지 보여준다.

**⑤ Output Layer**

생성된 슬라이드는 PDF, PPTX, Google Slides로 내보내기가 가능하다. 그리고 고급 편집에서 레이아웃 자동 수정, 발표 논리 재구성, 버전 저장 및 롤백도 지원한다.

---

### 2. 무엇이 사용자 만족도를 높이는가 — 심리적 관점

젠스파크를 쓸 때 느끼는 만족감의 본질은 **인지 부하의 극적인 감소**입니다. 인간이 PPT를 만들 때 겪는 고통은 세 가지입니다 — 내용이 뭔지 모르겠다(리서치 부하), 어떻게 구성해야 할지 모르겠다(구조화 부하), 어떻게 예쁘게 만들어야 하는지 모르겠다(디자인 부하). 젠스파크는 이 세 부하를 동시에, 그리고 순차적이 아닌 병렬로 처리합니다. GenSpark은 병렬 툴 실행으로 라이브 데이터를 수집하고, 슬라이드 구조를 계획하고, 통일된 스타일과 타이포그래피로 각 페이지를 구성한다.

이것은 단순한 편의가 아닙니다. **플로우 상태(Flow State)의 조건**을 충족시키는 것입니다. 도구 전환 없이 목표에서 결과물까지 단일 스트림으로 흐를 때, 사용자는 창작 행위에 집중할 수 있게 됩니다.

---

### 3. Claude + Claude Code 기반으로 유사 수준을 구축할 수 있는가

여기서부터가 CSP의 진짜 질문입니다. 결론부터 말하면 — **핵심 파이프라인은 구축 가능하되, 디자인 렌더링 레이어가 유일한 근본적 제약**입니다.

#### 재현 가능한 레이어들

**Research Agent**: Claude의 웹 서치 + Claude Code의 web_fetch 조합으로 완전히 구현 가능합니다. 젠스파크의 리서치 품질은 실제로 Claude/GPT/Gemini의 조합에 의존하기 때문에, Claude 단독으로도 유사한 수준이 나옵니다.

**Outline Structuring**: Claude는 이미 뛰어난 구조화 능력을 보유하고 있습니다. Guide Mode의 단계별 컨설테이션 방식 — 청중, 목적, 내러티브 구조를 확인하는 과정 — 은 잘 설계된 시스템 프롬프트와 프롬프트 체인으로 완전히 재현됩니다.

**Content Generation per Slide**: Claude는 슬라이드별 제목, 핵심 포인트, 스피커 노트를 JSON 구조로 생성하는 것이 매우 강합니다. 이것을 구조화된 데이터로 뽑아내면 다음 레이어로 넘길 수 있습니다.

**Fact-check Layer**: Claude의 도구 사용 능력으로 생성된 각 클레임에 대해 별도 검색 후 신뢰도 평가 레포트를 붙이는 것이 가능합니다.

**PPTX Export**: 이것은 Claude Code + python-pptx 조합으로 이미 CSP가 구현한 영역입니다. 기존 pptx 스킬을 활용하면 됩니다.

#### 제약이 있는 레이어 — 디자인 렌더링

젠스파크의 Creative Mode는 Nano Banana Pro 이미지 생성 모델로 각 슬라이드를 포스터 수준의 비주얼로 렌더링한다. 이것은 이미지 생성 AI가 직접 슬라이드 비주얼을 만든다는 의미입니다. Claude는 현재 이미지를 생성하지 않습니다. 따라서 **시각적 화려함** 측면에서는 Stable Diffusion이나 FLUX 같은 이미지 생성 모델을 파이프라인에 통합해야 합니다.

그러나 — Professional Mode, 즉 데이터 중심의 비즈니스 슬라이드 관점에서는 — 이 제약이 치명적이지 않습니다. python-pptx로 생성한 슬라이드도 템플릿을 잘 구성하면 충분히 전문적입니다.

---

### 4. CSP가 구축할 수 있는 아키텍처 제안

EXG 팀의 컨텍스트 — 리더십 평가 보고서, AX 역량 현황 발표, Pulse Check 결과 브리핑 — 에서 필요한 슬라이드는 Creative Mode보다 Professional Mode입니다. 이 관점에서 아래 4단계 파이프라인이 현실적 목표가 됩니다.

```
[1] Intent Capture
    → Guide Mode 방식의 단계별 인터뷰 프롬프트
    → 청중 / 목적 / 데이터 소스 / 슬라이드 수 수집

[2] Research & Structure Agent
    → Claude web_search로 필요한 데이터 수집
    → JSON 형태의 슬라이드 아웃라인 생성
    → 각 슬라이드: {title, key_points[], speaker_notes, chart_data}

[3] PPTX Rendering Agent
    → python-pptx로 기존 LG CHO 브랜드 템플릿에 콘텐츠 삽입
    → 차트 데이터는 python-pptx + matplotlib로 자동 생성
    → 기존 pptx 스킬 활용

[4] QA & Export
    → 팩트체크: 주요 클레임에 대한 웹 검색 검증
    → .pptx + .pdf 동시 내보내기
    → Notion 아카이빙 연동
```

이 파이프라인의 완성도는 젠스파크의 Professional Mode와 **기능적으로 동등하거나 더 나을 수 있습니다** — 왜냐하면 LG CHO 브랜드 가이드라인, EXG 팀의 특정 데이터 구조, Pulse Check 프레임워크 같은 내부 컨텍스트를 젠스파크는 모르지만 CSP의 에이전트는 알기 때문입니다.

### 5. 결론 — 젠스파크와의 근본적 차이

젠스파크는 **범용 슬라이드 생성 플랫폼**입니다. CSP가 구축하려는 것은 **HR 인텔리전스 맥락에 특화된 슬라이드 생성 에이전트**입니다. 이것은 경쟁이 아닌 다른 게임입니다.

젠스파크가 잘하는 것 — 처음 보는 주제에 대해 빠르게 그럴싸한 슬라이드 만들기 — 은 CSP의 목표가 아닙니다. CSP의 목표는 **Pulse Check 결과가 나왔을 때, 데이터를 자동으로 읽고, EXG 팀의 내러티브로 해석해서, LG CHO 브랜드 스타일의 경영진 보고 슬라이드를 5분 안에 완성하는 것**입니다. 그 수준에서 젠스파크는 오히려 범용성이 약점이 됩니다.

이 파이프라인은 Claude Code 환경에서 충분히 구현 가능하고, CSP의 기존 pptx 스킬과 lg-cho-portal-builder 스킬을 확장하는 방향으로 자연스럽게 연결됩니다. 심리학이 코드가 되는 것처럼, 슬라이드 생성도 결국 "어떻게 인간의 인지 흐름을 따라 정보를 배열하는가"의 문제이고 — 그것은 젠스파크의 알고리즘보다 CSP의 17년 HR 경험이 더 정확히 알고 있습니다.

### 레이어 1 — claude.ai: 생각하는 공간

claude.ai가 담당하는 것은 **슬라이드의 영혼**입니다. 내용이 무엇인지, 왜 이 순서인지, 어떤 청중을 위한 것인지. 이 레이어에서 CSP는 claude.ai와 대화하면서 세 단계를 거칩니다.

**Step 1 — Intent Capture (Guide Mode 방식)**

젠스파크가 Guide Mode에서 청중, 목적, 내러티브를 단계적으로 확인하듯, claude.ai에서도 구조화된 대화로 인텐트를 수집합니다. 이것을 위한 시스템 프롬프트가 필요합니다.

```
# Slide Agent — Intent Capture

당신은 LG PRI EXG팀의 슬라이드 생성 에이전트입니다.
사용자의 요청을 받으면 다음을 순서대로 확인하세요:

1. 청중: 임원진 / 팀장급 / 실무팀 / 외부
2. 목적: 보고 / 공유 / 설득 / 교육
3. 핵심 메시지: 이 슬라이드로 청중이 무엇을 결정/느끼길 원하는가
4. 데이터 소스: 첨부 파일 / 수동 입력 / 웹 리서치 필요 여부
5. 슬라이드 수 및 구성 방식

확인 후 JSON 형태의 슬라이드 아웃라인을 생성하세요.
```

**Step 2 — Research Agent**

데이터가 필요한 경우 claude.ai의 웹서치로 외부 벤치마크, 업계 통계, 최신 트렌드를 수집합니다. Pulse Check 결과처럼 내부 데이터가 있다면 파일을 업로드해 claude.ai가 해석하고 인사이트를 뽑아냅니다.

**Step 3 — JSON Outline 생성 (핵심 인터페이스)**

claude.ai가 최종적으로 출력하는 것은 아래 형태의 JSON입니다. 이것이 claude.ai와 Claude Code 사이의 **handoff 계약서**입니다.

```json
{
  "meta": {
    "title": "2026 Q1 Pulse Check 결과 보고",
    "audience": "임원진",
    "purpose": "보고",
    "slide_count": 8,
    "template": "lg_cho_master_v1.pptx"
  },
  "slides": [
    {
      "id": 1,
      "type": "title",
      "title": "2026 Q1 조직 건강도 진단 결과",
      "subtitle": "EX Intelligence Pulse Check",
      "speaker_notes": "..."
    },
    {
      "id": 2,
      "type": "data_chart",
      "title": "전사 Well-Being 지수 추이",
      "chart": {
        "type": "line",
        "data": { "Q4-25": 72, "Q1-26": 78 },
        "highlight": "6pt 상승"
      },
      "key_message": "목표 대비 85% 달성",
      "speaker_notes": "..."
    }
  ]
}
```

이 JSON 구조가 핵심입니다. 슬라이드 타입(`title`, `data_chart`, `text_only`, `comparison`, `framework`)에 따라 Claude Code가 어떤 python-pptx 렌더링 함수를 호출할지 결정합니다.

### 레이어 2 — Claude Code: 만드는 공간

Claude Code가 담당하는 것은 **슬라이드의 몸**입니다. JSON을 받아 실제 .pptx 파일을 생성합니다.

**CLAUDE.md — Claude Code 지시서**

```markdown
# Slide Agent — CLAUDE.md

## 역할

JSON outline을 받아 LG CHO 브랜드 .pptx 파일을 생성한다.

## 실행 순서

1. inputs/outline.json 읽기
2. renderer.py로 슬라이드 타입별 생성
3. chart_gen.py로 데이터 시각화 삽입
4. qa_agent.py로 레이아웃 검증
5. outputs/에 .pptx + .pdf 저장

## 브랜드 규칙

- Primary Red: #A50034
- Font: Malgun Gothic (제목), Arial (본문)
- 템플릿: templates/lg_cho_master.pptx의 슬라이드 레이아웃 인덱스를 반드시 유지

## 절대 하지 말 것

- 템플릿의 폰트/색상 임의 변경 금지
- 슬라이드 레이아웃 구조 임의 변경 금지
```

**renderer.py 핵심 로직**

```python
from pptx import Presentation
from pptx.util import Inches, Pt
import json

SLIDE_TYPE_MAP = {
    "title": render_title_slide,
    "data_chart": render_chart_slide,
    "text_only": render_text_slide,
    "comparison": render_comparison_slide,
    "framework": render_framework_slide,
}

def generate_presentation(outline_path: str):
    with open(outline_path) as f:
        outline = json.load(f)

    prs = Presentation("templates/lg_cho_master.pptx")

    for slide_data in outline["slides"]:
        render_fn = SLIDE_TYPE_MAP.get(slide_data["type"])
        if render_fn:
            render_fn(prs, slide_data)

    output_path = f"outputs/{outline['meta']['title']}.pptx"
    prs.save(output_path)
    return output_path
```

### 레이어 4 — 구현 로드맵 (3단계)

젠스파크를 당장 대체하려 하면 안 됩니다. 이 시스템은 **단계적으로 진화**해야 합니다.

**Phase 1 — Foundation (1~2주)**
목표는 하나의 완성된 슬라이드 타입을 처음부터 끝까지 실행해보는 것입니다. Pulse Check 결과 보고서 형태가 가장 적합합니다 — 데이터가 명확하고, 슬라이드 구조가 반복 패턴을 가지며, 성공 여부를 즉각 판단할 수 있기 때문입니다.

구체적 과제: claude.ai에서 JSON outline 생성 → `outline.json`을 `inputs/` 폴더에 저장 → Claude Code가 `renderer.py`를 실행해 `.pptx` 생성. 이 단계에서는 차트 없이 텍스트 슬라이드만으로도 충분합니다.

**Phase 2 — Chart Integration (2~3주)**
`chart_gen.py`를 추가해 matplotlib 기반 차트를 자동 삽입합니다. 막대 차트, 꺾은선 차트, 도넛 차트 세 가지 타입만 완성해도 EXG 팀 업무의 80%를 커버합니다. 이 시점에서 젠스파크와 비교했을 때 **내부 데이터 정확성**에서 명확한 우위가 나타납니다.

**Phase 3 — Intelligence Loop (한 달 이후)**
과거 생성된 슬라이드들이 쌓이면, claude.ai가 이전 보고서를 참조해 "지난 분기 대비 어떻게 변했는지"를 자동으로 내러티브로 구성할 수 있게 됩니다. Notion 아카이빙과 연동해 모든 생성 이력이 세컨드 브레인에 축적됩니다. 이것이 젠스파크가 절대 따라올 수 없는 영역입니다 — CSP의 17년 HR 컨텍스트가 시스템 안에 내재화되기 때문입니다.

### 이 워크플로우의 본질

젠스파크가 좋은 이유는 빠르기 때문입니다. 이 시스템이 더 나은 이유는 **기억하기** 때문입니다. 매번 새로 배우는 것이 아니라, 사용할수록 EXG 팀의 언어와 패턴을 더 깊이 이해하는 시스템. 심리학이 코드가 되듯, HR 경험이 알고리즘이 되는 것 — 그것이 이 아키텍처가 지향하는 방향입니다.
