Dispatch의 본질은 하나의 철학적 질문에서 출발합니다. **"나는 지금 생각하는 사람인가, 실행하는 사람인가?"** 이 둘이 섞이는 순간 생산성이 떨어집니다.

Dispatch가 생기면 달라지는 것은 이렇습니다.

```
This block is not supported on your current device yet.
```

핵심은 이겁니다. Dispatch 이전에는 **CSP가 Router**였습니다. "이건 PulseCheck 관련이니까 이 프롬프트로 가야지", "이건 ESCON이니까 저 컨텍스트를 다시 불러와야지" — 이 판단을 매번 CSP 본인이 하고 있었다는 뜻입니다. 그게 쌓이면 실질적인 창작 에너지가 라우팅 에너지로 소모됩니다.

Dispatch를 CLAUDE.md에 구현하면 **CSP는 의도만 던지면 됩니다.** "Pulse Check 이번 달 참여율 분석해줘" 한 마디가 들어오면, Dispatcher가 알아서 어느 Agent를 쓸지, 어떤 컨텍스트를 첨부할지, 어떤 출력 포맷이 필요한지를 결정합니다.

CSP의 워크플로우에 이게 구체적으로 적용되면 세 가지 생산성 지점이 생깁니다.

첫째, **컨텍스트 세팅 비용이 0에 수렴합니다.** 지금은 Claude Code를 열 때마다 "나는 LG PRI HR이고, 이 프로젝트는..." 식의 반복이 있습니다. Dispatcher가 들어온 명령의 키워드를 보고 자동으로 해당 CLAUDE.md와 Agent를 불러오면 이 비용이 사라집니다.

둘째, **멀티 프로젝트 병렬 처리가 가능해집니다.** PulseCheck, ESCON, EX Intelligence가 동시에 진행되는 지금, 각 프로젝트를 전환할 때마다 머릿속 컨텍스트 스위칭 비용이 큽니다. Dispatcher가 프로젝트 단위로 라우팅해주면 CSP는 결과만 받아서 판단하면 됩니다.

셋째, **추적 가능성이 생깁니다.** 어떤 요청이 어느 Agent를 통해 어떤 결과를 냈는지가 로그로 남으면, 나중에 "이 작업 방식이 맞았나?"를 돌아볼 수 있습니다. CSP가 목표로 하는 HR SaaS의 워크플로우 설계 역량이 여기서 증명됩니다.

### 작동 구조

핵심 구조는 이렇습니다. 폰 앱이 워키토키 역할을 하고, 실제 처리는 데스크탑 로컬 머신에서 일어납니다. 클라우드 컴퓨팅이 아니라 리모트 컨트롤입니다.

그리고 단발성 명령이 아니라, 데스크탑과 모바일을 가로지르는 **단일 지속 스레드**로 작동합니다. 대화가 리셋되지 않고, 이전 작업 맥락이 유지됩니다.

### 어제(3/23) 붙은 결정적 업그레이드

Dispatch와 함께 어제 발표된 것이 **컴퓨터 직접 제어** 기능입니다. Claude가 MCP 커넥터 없는 앱이라도, 화면을 직접 보면서 클릭하고 타이핑하며 작업을 완수합니다. Slack, Google Calendar 같은 커넥터가 있으면 그걸 쓰고, 없으면 사람처럼 화면을 조작하는 방식으로 폴백합니다.

### 셋업

Claude Desktop 설치 → Cowork 열기 → Dispatch 클릭 → 폰으로 QR 코드 스캔. 2분 이내로 완료됩니다.

### 조건과 제약

반드시 컴퓨터가 켜져 있어야 합니다. 맥이 슬립되거나 앱이 닫히면 Dispatch가 멈춥니다. 현재 macOS 전용 리서치 프리뷰이며, Max 플랜($100/월)이 먼저 접근 가능하고 Pro 플랜($20/월)은 며칠 내 순차 지원 예정입니다.

폴더를 지정하는 방법이 두 가지로 나뉩니다.

### 현재 알려진 버그

Dispatch 세션은 상위 프로젝트의 작업 디렉토리를 상속받지 못합니다. 프로젝트에 마운트된 폴더가 있어도 Dispatch 세션은 그걸 모릅니다. 게다가 경로 없이 `request_cowork_directory`를 호출하면 "path 파라미터가 필수"라는 에러가 나고, 명시적 경로로 넣어도 접근 불가 에러가 뜨는 경우가 있습니다.

초기 셋업 과정이 제대로 실행되지 않으면 Dispatch가 Cowork 폴더 권한을 상속받지 못하고, 이후에 설정을 수정할 방법도 없습니다.

### CSP에게 실용적인 워크어라운드

### 파일 저장 위치 — 세 가지 케이스

**정상적인 경우 (데스크탑 Cowork 세션)**

Claude가 파일을 생성하면 데스크탑의 Claude가 지정한 위치에 저장되고, 모바일에서 직접 접근하거나 데스크탑에서 Claude가 명시한 경로로 찾을 수 있습니다. 즉 저장 위치를 Claude가 작업 완료 메시지에 알려줍니다.

**Global Instructions로 고정하는 방법**

`Settings > Global Instructions`에 `"Put generated files in an /outputs subfolder"` 같은 규칙을 한 번 써두면 매 세션마다 같은 위치에 저장됩니다. 이게 가장 깔끔한 설정법입니다.

**Dispatch(모바일) 세션의 현실**

Dispatch 세션은 상위 프로젝트와 완전히 격리되어 있어서, 파일을 어디에 저장해야 하는지, 네이밍 컨벤션이 뭔지, CLAUDE.md가 뭔지 아무것도 모릅니다. `present_files` 권한도 거부되어 생성된 파일을 사용자에게 전달하는 신뢰할 만한 방법이 없습니다. 이건 현재 공식 버그로 올라가 있습니다.

**현재 워크어라운드**

워크스페이스 폴더를 Google Drive와 동기화해두는 것이 실용적인 해결책입니다. Dispatch가 데스크탑 폴더에 파일을 생성하면 Drive 동기화를 통해 폰에서 확인할 수 있습니다.

### 실제로 작동하는 방식

**Google Drive for Desktop 앱**을 설치하면, Drive가 로컬 폴더처럼 맥에 마운트됩니다. Cowork는 이 로컬 폴더에 파일을 저장하고, Drive 앱이 클라우드로 자동 동기화하는 구조입니다. Claude가 Drive에 직접 접근하는 게 아니라, 로컬 폴더 → Drive 앱 → 클라우드 순서로 연결되는 2단계 구조입니다.

즉 흐름이 이렇습니다.

```
폰에서 지시 → 데스크탑 Claude가 작업
→ 로컬 Drive 폴더에 저장
→ Google Drive 앱이 자동 동기화
→ 폰 Drive 앱에서 확인
```

### 정리

결국 핵심은 **Google Drive for Desktop 앱** 설치 여부입니다. 이게 없으면 Drive 연동 자체가 안 됩니다. 혹시 맥에 Google Drive for Desktop이 설치되어 있으신가요? 거기서부터 시작해야 경로가 명확해집니다.
