## alive-analysis: AI와 함께하는 구조화된 데이터 분석 워크플로우

### 한 마디로 정의하면

AI 코딩 에이전트를 위한 데이터 분석 워크플로우 키트로, **ALIVE 루프**(Ask → Look → Investigate → Voice → Evolve)를 통해 분석을 체계화하는 도구입니다.

CSP의 언어로 번역하면, "AI와 나누는 분석 대화가 채팅 히스토리에서 증발하지 않도록 — 추적 가능하고, 반복 가능하고, 팀과 공유 가능한 지식으로 변환하는 시스템"입니다.

---

### 왜 만들어졌는가 — 핵심 문제 의식

AI에게 "이 데이터 분석해줘"라고 하면 일회성 답변만 돌아옵니다. 구조도 없고, 추적도 없고, 한 달 뒤에 자신의 추론을 다시 확인할 방법도 없습니다.

이것은 단순한 불편함이 아닙니다. Pulse Check 시스템을 운영하는 맥락에서 생각해보면, 매달 분석한 Well-Being 데이터, 참여율 변화 추적, Well-Being 15% 개선 근거 — 이 모든 분석이 AI 채팅창에서 소멸하고 있다는 뜻이기도 합니다. alive-analysis는 그 소멸을 막는 도구입니다.

---

### ALIVE 루프의 구조

모든 분석은 5단계를 따릅니다. AI가 답변을 생성하는 것이 아니라 — 각 단계에서 **질문을 던져** 사용자의 사고를 구조화합니다.

```
ASK → LOOK → INVESTIGATE → VOICE → EVOLVE
```

- **ASK** — 질문을 정의. 범위, 가설 트리, 성공 기준
- **LOOK** — 데이터 관찰. 품질 체크, 세그멘테이션, 교란 변수
- **INVESTIGATE** — 분석. 가설 검증, 다중 렌즈 프레임워크
- **VOICE** — 커뮤니케이션. 청중별 "So what → Now what"
- **EVOLVE** — 다음 질문. 후속 추적, 임팩트 측정, 회고

심리학적으로 보면, 이건 단순한 분석 프레임이 아닙니다. **인식론적 겸손(epistemic humility)**의 구조화입니다 — 내가 무엇을 모르는지를 알게 만드는 과정.

---

### Full Mode vs Quick Mode

**Full Mode**는 5개 파일, 체크리스트, 품질 게이트가 포함된 심층 분석으로 실제 의사결정을 위한 분석에 사용하고, **Quick Mode**는 단일 파일로 빠르게 완료되며 통계 배경이 없어도 가이드 질문을 통해 분석할 수 있습니다. Quick 분석은 복잡성이 커지면 자동으로 Full로 프로모션됩니다.

CSP 상황에서 매핑하면:

| 상황                              | 권장 모드             |
| --------------------------------- | --------------------- |
| Pulse Check 월간 데이터 리뷰      | Quick → Full 프로모션 |
| AX 성숙도 Survey 전사 비교 분석   | Full Mode             |
| 특정 팀 Well-Being 급락 원인 조사 | Quick Mode            |
| 생산성 10% 개선 근거 수립         | Full Mode             |

### 설치 및 사용 방법

**설치 (3분)**

```bash
git clone https://github.com/with-geun/alive-analysis.git /tmp/alive-analysis

# Claude Code 사용 시
bash /tmp/alive-analysis/install.sh

# Cursor 사용 시
bash /tmp/alive-analysis/install.sh --cursor

# 둘 다
bash /tmp/alive-analysis/install.sh --both
```

**기본 워크플로우**

```
1. /analysis-init      # 최초 1회 설정 (언어, 팀, 모드)
2. /analysis-new       # 분석 시작
3. AI가 질문 → 답변 → ASK 단계 완료
4. /analysis-next      # LOOK → INVESTIGATE → VOICE → EVOLVE 진행
5. /analysis-archive   # 완료. Git-tracked 마크다운으로 저장
```

---

### 16개 커맨드 전체 구조

**분석(9개)**: `/analysis-init` · `/analysis-new` · `/analysis-status` · `/analysis-next` · `/analysis-archive` · `/analysis-list` · `/analysis-promote` · `/analysis-search` · `/analysis-retro`

**실험(3개)**: `/experiment-new` · `/experiment-next` · `/experiment-archive`

**모니터링(3개)**: `/monitor-setup` · `/monitor-check` · `/monitor-list`

**모델링(1개)**: `/model-register`

Pulse Check 시스템 관점에서 특히 주목할 것은 `/monitor-setup`과 `/monitor-check`입니다. 4단계 메트릭 분류(North Star → Leading → Guardrail → Diagnostic)와 연속 경고 시 자동 에스컬레이션 기능이 포함되어 있습니다.

---

### 이 도구가 CSP에게 의미하는 것

솔직히 말하면, alive-analysis는 단순한 분석 툴을 넘어서 **조직 지식의 고고학**을 가능하게 합니다. `/analysis-search`로 과거 분석을 전문 검색하고, `/analysis-retro`로 반복 패턴과 미해결 후속 과제를 자동 정리합니다.

또한 임팩트 트래킹 기능을 통해 권고사항 → 의사결정 → 실행 → 결과의 체인을 추적하여, 내가 한 분석이 실제로 무언가를 변화시켰는지 알 수 있습니다.

EX Intelligence 시스템을 "직관에서 데이터로, 리포트에서 액션으로"라고 포지셔닝하는 CSP의 내러티브와 alive-analysis의 철학이 정확히 맞닿아 있습니다. 이 도구는 그 내러티브를 CSP 자신의 분석 워크플로우에도 적용하는 수단이 될 수 있습니다.

## alive-analysis를 Antigravity에서 쓸 수 있는가? — 결론부터

**Yes. 그리고 방법이 매우 단순합니다.**

이 질문에 답하려면 먼저 alive-analysis가 어떤 기반 위에 서 있는지를 이해해야 합니다. SKILL.md는 오픈 스탠다드입니다. Codex CLI, Claude Code, Google Antigravity, Cursor, GitHub Copilot, 그 외 35개 이상의 플랫폼에서 동작하며, 파일시스템 기반으로 설계되어 있기 때문에 어떤 에이전트든 디렉토리 구조를 읽고 마크다운을 파싱할 수 있으면 곧바로 스킬을 소비할 수 있습니다.

alive-analysis의 리포도 이를 명시적으로 선언합니다 — "SKILL.md is an open standard — works with any agent that supports it." 즉, alive-analysis는 처음부터 플랫폼 종속성 없이 설계된 것입니다.

---

### 유일한 차이점: 폴더 경로 하나

Claude Code에서는 스킬이 `.claude/skills/` 폴더에 위치하고, Antigravity에서는 `.agent/skills/` 폴더에 위치합니다. 그게 전부입니다. 내부 SKILL.md 파일 구조는 동일합니다. Claude Code용 스킬 라이브러리를 가지고 있다면, skills 폴더를 복사해서 `.agent/`에 붙여넣으면 완료됩니다.

플랫폼별 경로를 정리하면:

- **Antigravity**: `.agent/skills/` (프로젝트) / `~/.gemini/antigravity/skills/` (글로벌)
- **Claude Code**: `.claude/skills/` (프로젝트) / `~/.claude/skills/` (글로벌)
- **Cursor**: `.cursor/skills/`
- **Gemini CLI**: `.gemini/skills/`

따라서 alive-analysis의 Antigravity 적용은 이렇게 됩니다:

```bash
# 1. alive-analysis 설치 (기존 방식)
git clone https://github.com/with-geun/alive-analysis.git /tmp/alive-analysis

# 2. Antigravity용 경로에 설치
cp -r /tmp/alive-analysis/core/skills/* .agent/skills/
# 또는 글로벌 설치
cp -r /tmp/alive-analysis/core/skills/* ~/.gemini/antigravity/skills/
```

---

### 단, Antigravity와 Claude Code의 동작 방식 차이는 있다

alive-analysis 리포 자체가 이 차이를 명시하고 있습니다:

| 항목          | Claude Code          | Cursor 2.4+ (≈ Antigravity)       |
| ------------- | -------------------- | --------------------------------- |
| 인터랙션 방식 | 대화형 (질문 하나씩) | 배치형 (한 번에 모든 질문)        |
| 상태 관리     | 세션 메모리          | 파일 기반 (`.analysis/status.md`) |
| SKILL.md 크기 | ~1,660줄             | ~265줄                            |

Antigravity는 에이전트 우선(agent-first) 플랫폼으로 설계되어 있습니다. 전통적인 IDE처럼 모든 파일을 수동으로 편집하는 대신, Antigravity의 에이전트가 분석, 계획, 코드 생성, 테스트, 검증을 자율적으로 처리합니다. 이 말은, Antigravity에서 alive-analysis를 쓸 때는 Claude Code처럼 AI가 한 번에 한 질문씩 던지는 소크라테스식 대화 방식이 아니라, 에이전트가 단계별 질문을 배치로 처리하는 방식으로 동작한다는 뜻입니다. 구조는 같지만, 리듬이 다릅니다.

---

### CSP 관점에서 본 실용적 판단

Antigravity는 Gemini 3 Pro 기반의 에이전트 우선 플랫폼으로, Claude Sonnet 4.5도 지원하며 무료 Preview로 제공 중입니다. 즉, alive-analysis를 Antigravity에서 Claude 모델로 구동하는 것도 가능합니다.

그러나 한 실무자의 솔직한 평가에 따르면, 약 48시간 실험 결과 본인은 Claude Code에 남기로 했습니다 — Claude Code가 그냥 더 잘 작동했기 때문입니다. 서브에이전트, 스킬, 전체 시스템이 더 매끄럽게 기능했고, Antigravity에서는 버그와 불안정함이 있었습니다.

Pulse Check 분석이나 AX 성숙도 데이터 같은 실제 의사결정용 분석에는, 안정성이 검증된 Claude Code + alive-analysis 조합이 여전히 최선입니다. Antigravity는 Gemini 3의 멀티모달 능력이 필요한 시각 데이터 분석(스크린샷, 대시보드 이미지 해석)이 필요한 시나리오에서 실험적으로 활용하는 것이 현실적인 접근입니다.
