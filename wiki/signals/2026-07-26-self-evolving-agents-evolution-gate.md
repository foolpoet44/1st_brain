# [Signal] 2026-07-26: 자기진화 에이전트와 Evolution Gate

## 1. 개요 (Capture)

2026년 HR Tech의 담론은 "에이전트가 무엇을 할 수 있는가"에서 **"에이전트가 스스로 변할 때 누가 그 방향을 결정하는가"**로 이동했다. arXiv 서베이는 자기진화 에이전트를 "폐루프 피드백을 통해 내부 모델·메모리·도구셋을 지속적으로 수정하는 자율 시스템"으로 정의한다. 채용에 적용되면 에이전트는 **후보자 데이터를 처리할 때마다 자신의 평가 기준을 갱신**한다.

문제는 이 갱신이 인간의 감사 없이 일어날 수 있다는 점이다. [[2026-07-22-autonomous-hiring-paradox]]가 "누가 결정하는가"를 물었다면, 이 신호는 **"누가 결정 기준의 변경을 승인하는가"**를 묻는다. 한 단계 위의 질문이다.

---

## 2. 핵심 신호 (Key Indicators)

### 2.1. 자기진화의 실증 성능

- **Intra-task 진화**: 단일 에피소드 내 반성(reflection)·오류 수정·온라인 정책 탐색으로 적응
- **Inter-task 진화**: 여러 태스크를 거치며 워크플로우·메모리를 통합 — 인간의 경험적 학습을 모방
- **성능**: Text-to-SQL(RoboPhD)에서 +2~8.9pp, 생산성 벤치마크(MUSE)에서 +8.6pp SOTA

### 2.2. Multiplayer HR — 에이전트 간 상호작용의 등장

Recruitics는 **에이전트 오케스트레이션**을 2026년 최대 트렌드로 지목한다. Recruiter Agent ↔ Candidate Agent ↔ Manager Agent가 서로 상호작용하는 구조에서, CHRO의 새 책임은 **HR 콘텐츠를 인간이 읽을 수 있을 뿐 아니라 기계가 해석할 수 있는 형태로도 설계**하는 것이다.

에이전트 간 충돌 지점이 새로운 관리 대상이 된다 — 우선순위 조정(동시 접근), 정보 일관성(Recruiter Agent는 "합격", Candidate Agent는 "대기중"), 합의 실패 시 인간 에스컬레이션.

### 2.3. 설명 가능성의 제도화

LinkedIn 2026 보고서에서 **93%의 채용 담당자**가 AI 사용 확대를 계획하면서도 동시에 "AI는 결정하지 않는다"는 원칙을 재확인했다. Testlify가 정리한 구현 요건은 역량 기반 매칭, 매치 스코어 공개, 기여 시그널 추적 가능성, 인간 검토 옵션 네 가지다.

## 3. 도메인적 통찰 (Domain Insight)

### 3.1. 진화는 인간을 배제하지 않고, 인간의 역할을 재정의한다

자기진화 에이전트는 HR에 실존적 질문을 던진다 — _"에이전트가 스스로 학습한다면 나는 무엇을 하는 존재인가?"_

자기결정성 이론(SDT) 렌즈로 보면 세 축이 모두 흔들린다. **자율성**은 에이전트가 진화할수록 인간 통제력이 줄어들며 위협받고, **유능감**은 평가 역량의 위축으로 훼손된다(폴란드 대장내시경 연구: AI 도입 3개월 후 AI 없이 용종 발견율 6%p 감소). 다만 **관계성**은 역설적으로 가치가 부각된다 — 에이전트 간 상호작용이 늘수록 인간 간 관계는 희소해지기 때문이다.

칸트의 계몽 정의를 빌리면, 2026년 HR의 계몽이란 **AI에게 진화를 위임하되 그 진화의 방향을 설계하는 책임은 인간이 유지하는 것**이다. 수동적 감독이 아니라 능동적 지휘다.

### 3.2. 신뢰는 투명성이 아니라 투명성의 *사용법*에서 나온다

Explainable AI가 제공하는 "이유"는 도구일 뿐 해결책이 아니다. 채용 담당자가 그 이유를 어떻게 쓰는가가 신뢰를 만든다. 여기서 **신뢰 사다리 3단계**가 도출된다.

1. **맹신(Blind Faith)** — "AI가 탈락시켰으니 탈락이다"
2. **불신(Distrust)** — "AI는 틀릴 수 있다"
3. **협력(Collaboration)** — "AI는 이렇게 판단했다. 나는 이 판단을 어떻게 검증할 것인가?"

[[sf-domain-mapping]]의 Trust Level Disclosure는 3단계로 올라가기 위한 구조적 장치다. "이 평가의 신뢰도는 낮음(low), 인간 개입 필요"라는 명시가 인간 게이트를 **활성화**시킨다.

## 4. Evolution Gate 설계 명세

[[bp-signal-intelligence]]의 스키마를 다음과 같이 확장할 것을 제안한다. 자기진화 시대에는 신호 자체의 진화도 관리 대상이 되기 때문이다.

```yaml
# 기존
action_tier: alert | review | monitor | ignore
confidence: high | medium | low

# 확장
evolution_gate:
  required: true # 에이전트 모델 수정 시 인간 승인 필수
  audit_log: true # 어떤 데이터가 진화를 촉발했는지 기록
  rollback_enabled: true # 인간이 언제든 이전 버전으로 복원
  validation_sample: 10 # 분기별 무작위 검증 샘플 수
```

**3단계 인간 게이트**

| 게이트 | 시점             | 인간의 판단      |
| :----- | :--------------- | :--------------- |
| Gate 1 | 모델 수정 제안   | 승인 / 거부      |
| Gate 2 | A/B 테스트 결과  | 배포 승인        |
| Gate 3 | 분기별 진화 감사 | 진화 방향성 검증 |

설계 원칙은 네 가지다. 모든 수정은 git 커밋처럼 **추적 가능**해야 하고, 진화를 촉발한 데이터는 **기록**되어야 하며, 인간은 언제든 **롤백**할 수 있어야 하고, 새 모델은 이전 모델보다 **통계적으로 유의미하게 우수할 때만** 승인된다.

## 5. 인간 게이트 4종 (2026-07-29 브리핑 병합)

07-29 브리핑은 같은 문제를 시장 데이터 쪽에서 접근해 네 개의 게이트를 도출했다. 통계적 배경이 다르므로 함께 기록한다.

| #   | 게이트                        | 트리거                                                             | 근거 통계                                                                                       |
| :-- | :---------------------------- | :----------------------------------------------------------------- | :---------------------------------------------------------------------------------------------- |
| 1   | **에이전트 진화 감사**        | 분기별 무작위 10개 샘플을 인간이 검증                              | 87%가 AI를 쓰지만 **단 20%만 end-to-end 오케스트레이션** 보유                                   |
| 2   | **알고리즘 집중도 한도 심사** | 특정 대학/기업 출신이 최종 합격자의 **30% 초과** 시 인간 감사 발동 | 81%가 스킬 기반 채용을 채택했다지만 **37%만 학력을 신뢰 가능 신호로 인정** — 표면과 실제의 괴리 |
| 3   | **후보자 신뢰도 점수 공개**   | 신뢰 수준 Medium 이하면 인간 재심사 필수                           | 미국 성인 **71%가 AI의 최종 채용 결정에 반대**                                                  |
| 4   | **3단계 진화 게이트**         | 수정 제안 → A/B 테스트 → 분기 감사                                 | arXiv:2507.21046 — 에이전트가 스스로를 **악화시킬 수도** 있음                                   |

게이트 2가 특히 중요하다. 조직은 표면적으로 "스킬 기반"을 외치지만 내면적으로는 **학력이라는 휴리스틱**에 의존한다. 이것은 개인의 위선이 아니라 **집단적 인지부조화**이며, 따라서 개인의 각성이 아니라 **구조적 트리거**로만 교정된다. 30% 한도는 그 트리거의 구체적 형태다.

### 감시자 → 정원사

07-29 브리핑이 정리한 정체성 대비는 이 문서 전체를 관통한다.

**감시자(Guardian)**는 규칙을 집행한다. "요건 미충족 → 탈락." 감시자에게 AI는 자동화된 심판이며, AI가 탈락시키면 "AI가 그렇게 판단했다"는 이유로 **책임을 위임**한다. 신뢰 사다리 1단계다.

**정원사(Gardener)**는 연결을 관찰한다. "이 후보자는 전통적 요건을 충족하지 않지만, 이 스킬은 우리 조직의 어떤 문제와 연결될 수 있는가?" 정원사에게 AI는 **가설 생성기**다. 3단계다.

차이는 태도가 아니라 **책임의 소재**다. 감시자는 판단을 위임하고 정원사는 검증을 수행한다. Evolution Gate는 이 전환을 개인의 성숙에 맡기지 않고 **시스템에 못 박는 장치**다.
